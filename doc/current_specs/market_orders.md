# 限价模拟市价与 IOC

## 接口语义

`POST /cfb/create_market_order` 使用限价 IOC 模拟市价效果，允许部分成交，剩余量由柜台按 IOC 撤销。它不是原生市价，不采用成交后主动撤单或自动追价。请求沿用 [HTTP 接口](api.md)，不接受 price、time_in_force；execution 明确返回 emulated_market、实际 price 和 IOC。

买入采用终端当前合约涨停价，卖出采用跌停价。此价格是可接受的边界，不等于成交价格；实际按撮合结果成交，可能部分成交、零成交或拒单。模拟市价发送前要求快期原生状态为连续交易，涨跌停、步长和限价手数资料有效；不使用日历或通知推断可交易。

普通投机开仓和普通平仓共用该流程。指定平今/平昨、套利/套保、投资单元等独立限制按公共能力规则处理。实盘和模拟盘共用实现，AI 在线写操作只允许明确授权的模拟账户。

## 参数和执行链路

限价手数来自 Instrument_MinLimitOrderVolume/MaxLimitOrderVolume，步长和涨跌停来自快期合约对象。缺失资料报 503，非连续交易报 409/MARKET_NOT_TRADING，用户手数或限价越界报 422。一次请求只发送一次，不自动拆单，不降级到 GFD。

固定版本 CSV 导入不能表达 IOC，因此显式限价 IOC 与模拟市价复用下单板路径；普通限价 GFD 仍用无弹窗 CSV 导入。

1. 核对环境、会话和合约，保存委托、成交、持仓 CSV 基线。
2. 保存下单板原来的合约、手数、价格、买卖、开平及有效期。
3. 填写明确的数值限价，通过原生控件焦点设置买卖、开平；从原生菜单选择并回读 FAK。
4. 打开“预埋/条件”，核对手动发出选项和完整数值价格摘要，创建本地预埋单。
5. CSV 确认只增加唯一匹配记录，其他记录不变；只读原生字段核对限价和 IOC。
6. 唯一选中目标，以 Alt+Q 发送一次；本地已发送状态确认提交。
7. 捕获实际发送的报单引用，依照 [终端执行器](terminal_execution.md) 精确关联订单及成交，并有界回读 CSV。
8. 删除本次本地记录，恢复并回读原下单板，交还 GUI 执行权。

控件按进程、层级、编号和文字定位，不使用固定屏幕坐标或 OCR，不按直接下单按钮，不调用内部交易函数。未知模式或窗口在发送前报错；已发送后失败仍保留提交事实。

## 原生参数核对

GetParkedOrderList/ParkedOrder_Id 提供本次创建游标；CSV 和原生快照共同要求新增记录唯一，身份及参数一致。不得据此推断交易所订单编号。

固定版本数值限价要求 ParkedOrder_OrderPriceSelector=105、TimeCondition=1、VolumeCondition=1，表示数值限价、IOC、任意数量；ParkedOrder_LimitPrice 必须与实际限价一致。原生方向 0/1 为买/卖，开平 0/3 为开仓/普通平仓，投机为 1。这些是快期内部枚举，不能套用 CTP 字符编码。市价选择器 104、GFD 或 FOK 条件不能通过此链路。

读取在已绑定 GUI 线程及现有 FIFO 执行权内完成，沿用程序和核心 DLL 哈希检查；每次释放列表，不跨会话保存裸指针。只读取身份与委托参数，交易状态由 CSV 读取。

账户可能还有人工原生市价单，其 CSV 价格“市价”或“市价/保护价”仍解析为 price=null，不会导致查询整张快照失败；模拟市价实际是数值限价，查询 price 为该数值。

## 通知、确认和防重发

下单成功、下单失败、即时单撤单成功/失败（包括批次编号标题）、成交通知只负责记录和关闭。通知不证明本次订单被接受、拒绝或成交，且不改变 verification 的结果。模板、去重、期限及恢复规则统一在终端执行规范维护。

正常返回 202/submitted 和实际 identity；verification 的委托与成交通过完整引用精确关联，已分配时返回真实 order_id。没有即时回报或成交尚未到齐保留 pending，身份冲突为 ambiguous，读取失败为 unavailable；不因此重新发送。捕获缺失或入口恢复失败按未知结果隔离，不回退到参数候选。相关字段和按引用查询示例见 HTTP 接口规范。

离线核验价格选择、手数边界、原生限价 IOC 条件、CSV 差异和失败语义；在线须分别核对真实限价、IOC、柜台接受、成交与剩余量处理。界面填写成功或静态检查通过不等于模拟交易验证通过。
