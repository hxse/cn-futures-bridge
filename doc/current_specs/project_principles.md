# 项目基调与适配原则

## 高性能与可靠性

整个项目以高性能、可靠为共同目标，适用于终端适配、查询、交易、异常处理和 REST 封装。性能优化须保留参数核对、目标身份确认、结果校验和异常处理；可靠性须由实际业务结果证明，不能仅凭按键返回、窗口消失或文件生成判断成功。

本文规定当前有效的选型与验证原则，不表示所有能力已经实现。正式接口范围见 [bootstrap.md](bootstrap.md)，已验证能力、性能口径及剩余边界见 [terminal_capabilities.md](terminal_capabilities.md)。

## 操作方式的优先级

1. **第一优先：无弹窗 CSV 主链。** 交易采用“CSV 导入参数 → CSV 回读核对 → 快捷键发送 → CSV 读取委托和成交回报”，其中导入、回读及回报读取均使用无弹窗方式；支持 CSV 的表格查询直接无弹窗导出并校验。
2. **第二优先：快捷键。** 某项需求或某个环节无法通过第一优先方案可靠完成时，采用已验证的快捷键，并核对目标、参数及执行结果。
3. **最后选择：直接操作 GUI。** 前两种方式均不能满足需求时，才使用控件定位、原生文本读取及必要的鼠标操作；可读取原生控件时优先使用控件，像素或 OCR 识别仅补充无法直接取得的信息。

优先级按具体需求和环节选择。某项操作需要快捷键或直接 GUI，不改变其他已支持操作采用无弹窗 CSV 的优先级。查询资金、撤单、条件单管理等均按此原则确定各自路径，不要求强行套用交易四步流程。

交易状态采用已选定的专用路径：读取已登录快期进程中的品种/合约原生状态，具体能力见 [trading_status.md](trading_status.md)。不使用交易日历、时段表、本机时钟或模拟环境时间规则推算，也不以交易所颜色汇总代替品种状态；读取失败明确报错。这一选择不改变其他查询与交易的 CSV 优先级，原生状态读取仍须统一串行、校验版本和会话。

VNC 用于调试和必要的人工查看，正常自动化不依赖有人观看或连接 VNC；无弹窗方式仍由运行中的终端及图形会话承载。

## 可靠性约束

- 发出交易前，回读并核对合约、买卖、开平、价格、数量及目标记录；导入成功、本地已发送、柜台接受和成交分别判断，不能混为同一成功状态。
- 导入须处理逐条错误、部分成功及重复记录；请求去重、目标关联和结果未知的恢复不能因追求速度而省略。查询须校验本轮数据、完整性及新鲜度，不能用旧文件或默认零值掩盖失败。
- 优先级用于选择具备相应能力的路径，不是遇到错误后自动换路径重做交易。已经导入、发送或结果不明时，先核对本地记录、委托和成交回报，不能因超时改用另一种方式重复下单。
- 使用快捷键或直接 GUI 时须确认窗口、页面与焦点；遇到未知弹窗、绑定失效或无法确认的结果，保留错误证据并停止相关操作。已选定的无弹窗业务导出失败时明确报错，不静默退回弹窗导出。
- 实现优先级与验证覆盖分别记录；成功导入不代表成功交易，空表验证不代表非空表验证，固定版本样本不代表升级后继续兼容。

## 性能判断

比较方案时保持业务目标、数据规模、校验内容和计时终点一致，关注完整链路的耗时、尾部延迟、错误和超时。分别标明本地准备、发送动作、柜台回报以及 HTTP 排队等成本；不能将局部调用耗时当作完整业务耗时。

优先省去文件选择与结果提示弹窗、不必要的页面切换、鼠标定位和重复进程启动，复用仍有效的连接、进程与表格绑定。优化后仍须满足相同的正确性及异常处理要求，不以跳过核对或返回旧数据换取更低耗时。
