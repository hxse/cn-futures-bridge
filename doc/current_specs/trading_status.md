# 快期原生交易状态读取

## 能力与适用范围

当前已选定从已登录快期2进程内读取其维护的交易状态。该能力已有 SimNow 只读探针依据，正式 [终端执行器](terminal_execution.md) 已实现固定版本校验、二值返回及会话门禁；HTTP 路由见 [api.md](api.md)。

原生读取不依赖 CSV、快捷键、鼠标悬停、状态栏颜色或 OCR；也不根据日历、时间段或模拟站点名称推算开市。它使用快期已有会话和数据，不新建 CTP 登录、认证或交易连接，不通过发送订单探测开市。

## 固定版本与数据入口

适用客户端为 `2.93.405.1998`、32 位 Wine 11.0；当前 Wine 构建见 [bootstrap.md](bootstrap.md)，完整能力边界见 [terminal_capabilities.md](terminal_capabilities.md)。以下是已验证程序文件身份，不是调用方可配置的任意 DLL 路径：

| 文件 | SHA256 |
| --- | --- |
| `q7_release.exe` | `77508f5729b74db4bdaa586bc6c354e71fad29ad8d1250cced3c5c7293a7eca9` |
| `shinny_future_core.dll` | `da4b54b234bf5fd3b86367028f9aad8f0c431cddadfa6a8244652f5aa16ba56f` |

入口来自快期已经加载的 `shinny_future_core.dll`，属于非公开内部函数，不是官方开放 SDK。正式 helper 在客户端 GUI 线程中串行调用，复用已登录进程中的对象；在外部独立加载 DLL 不等于取得该会话。

| 范围 | 查找与读取入口 | 当前边界 |
| --- | --- | --- |
| 品种 | `GetProductLike` → `Product_Id`、`Product_ExchangeID`、`Product_Status` | 以实际返回身份核对输入，不能把模糊匹配或大小写补全当作精确命中 |
| 合约 | `GetInstrumentIgnoreCase` → `Instrument_Id`、`Instrument_ExchangeId`、`Instrument_Status` | 核对实际合约及交易所；不由交易所总状态替代 |
| 交易所 | `GetExchange` → `Exchange_Status` | 仅代表交易所范围，可辅助核对，不能回答指定品种是否处于连续交易 |

关键状态导出符号为 `?Product_Status@@YAJPBUProduct@@@Z`、`?Instrument_Status@@YAJPBUInstrument@@@Z`、`?Exchange_Status@@YAJPBUExchange@@@Z`，均为接收相应只读对象指针、返回 32 位 long 的 cdecl 函数。客户端内交易所编号为 SHFE=1、DCE=2、CZCE=3、CFFEX=4、INE=5、GFEX=6；这些私有编号不冒充 CTP 编码。

对象查找或模块导出失败不能继续解引用。版本、位数、符号或会话不匹配须停止该读取，不能跳过校验、复用旧裸指针或静默退回颜色/日历。正式适配纳入受控源码与构建，不能依赖临时探针路径。

## 原生状态语义

固定版本程序中的状态文字映射如下；这是快期内部枚举，不能直接套用 CTP 字符枚举：

| 原生值 | 状态文字 |
| --- | --- |
| 0 | 未知 |
| 1 | 开盘前 |
| 2 | 非交易 |
| 3 | 连续交易 |
| 4 | 集合竞价报单 |
| 5 | 集合竞价价格平衡 |
| 6 | 集合竞价撮合 |
| 7 | 收盘 |

二值业务语义采用“是否连续交易”：3 为开盘，1、2、4、5、6、7 为非连续交易；集合竞价归入后一类不表示该阶段禁止所有报撤单。0、未知编码或读取失败不能转换为休盘。该值不证明账户资金、权限或某笔委托会被接受。

## 已确认事实与验证边界

RM、ad、rb、au、IF 品种，RM701、ad2610、rb2610、au2612、IF2610 合约及六个交易所均取得原生 7/收盘值。不存在的测试标的返回空指针；`rm` 查找会返回实际身份 `RM`，带前缀的 `CZCE.RM` 未命中，调用方必须自行核对身份。

最小调试读数为 `product RM exchange 3 status 7`，该探针格式不是正式 HTTP 返回形状。六个交易所的状态栏内部提示缓存也可读到名称及“收盘”，无需实际悬停；[官方状态栏说明](https://doc.shinnytech.com/q72/latest/9.html) 仅佐证显示用途，原生函数能力依据固定版本探针。

原生状态各阶段与切换需分别验证。枚举映射的静态核对和历史颜色切换样本，均不能替代原生路径的开盘/休盘切换、集合竞价、夜盘品种差异、断线重连和重启刷新验证；断线时旧状态仍可能留在内存，取得整数不等于会话有效。

正式读取需在同一请求执行权内核对连接和会话代次，再查询品种状态；断线、重启或会话变化后旧绑定和数据可信标记失效，完成新会话核对及刷新验证前不能返回旧值。状态请求不触发自动重登，也不为读取而切页、按复位键或额外固定 sleep；前后共用基线扫描处理已识别通知，通知不参与开市状态判断。

## 性能口径

固定 Wine 11 的已登录 VNC 容器中，常驻控制器查询 RM 的 100 次样本：中位数 0.35 ms、P95 1.24 ms、最大 7.51 ms；一次控制器启动约 79.29 ms、首次查询约 2.64 ms。计时包含容器内本地通信往返，正常请求之间间隔 10 ms，间隔不计入单次耗时。

这些数值不含 HTTP、业务队列、正式会话/连接门禁及完整日志成本，也不是持续负载或生产时延承诺。性能验证须将启动与常驻查询分开，并保持身份校验、状态语义和计时终点一致。
