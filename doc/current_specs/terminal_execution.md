# 单账户终端执行器

## 所有权与业务链路

FastAPI 所属服务持有数据目录排他锁、单个有界 FIFO 和调度线程；独立 Python 执行器拥有常驻 Wine 控制器。原生 helper 源码位于 native，镜像构建时使用 32 位 MinGW 严格编译，运行镜像只复制产物，不加载 debug 探针。

业务请求通过 Pydantic Operation/请求模型校验，再交给执行器。IPC 使用带代次、逻辑编号和派发期限的有界 JSON。队列容量默认 32，排队期限 5000 ms；过期或开始前取消的请求移除且不执行。HTTP 取消不终止已经开始的终端动作，也不释放 GUI 所有权。

原生消息超时可能仍在 GUI 线程执行，控制器保留映射，执行器标记 poisoned 并停止派发。此时不能仅通过 resume 重新使用；须先受控停止整个专属 Wine 会话，再重启容器。停止不会撤销柜台订单或重放队列。

| 动作 | 正式内部实现 |
| --- | --- |
| 限价 GFD 开仓/普通平仓 | 无弹窗 CSV 导入一条手动预埋单 → CSV 回读逐项核对 → 唯一定位 → Alt+Q → 本地已发送状态 → 一次订单快照 |
| 按交易所编号撤单 | 无弹窗活动订单 CSV → 精确合约/编号 → 唯一选择 → Delete → 原生确认文字核对 → Enter |
| 订单/逐笔成交/持仓 | 无弹窗导出完整筛选范围，GB18030 严格解析与本地过滤 |
| 资金 | 原生定位查询按钮 → Space → 资金详情控件文字 → 服务器列解析 → Esc 关闭 |
| 品种交易状态 | 已登录 GUI 线程内 GetProductLike/Product_Status，身份精确核对、原生状态二值映射 |

表格定位核对窗口、ListCtrl 对象及固定列布局；确认筛选范围，必要时用 F3/F4/F5/F6/F8 定位。绑定有效且筛选正确时，CSV 不强制切页、不打开导出窗口。选择行通过固定版本原生 GUI 选择函数并核对选中数/索引，选后再次回读身份；发送和撤单仍是快捷键，不调用内部交易函数。

参数相同的既有手动预埋单会使本次目标不唯一，发送前拒绝；不覆盖或删除人工记录。本次记录以完整参数及客户端预埋时间绑定，状态与说明变化不改变身份。收尾只删除能够唯一归属本次操作的本地记录，不撤销柜台订单。CSV 字段、编码、行宽或必需身份无效时返回读取错误，不伪装成空数组。

仅支持已验证主路径；市价、IOC/FOK、指定平今/平昨、非投机报单、会话编号撤单保持 unverified，执行前返回 CAPABILITY_NOT_SUPPORTED。非空投资单元和非 CNY 资金当前为 unsupported。capabilities 的 supported 表示基础适配路径具备依据，不保证任意账户、合约或时段能够下单；正式集成的完整在线闭环仍需实测。

## 登录、连接与界面基线

每次受控启动只使用 bridge.mode 选中的 accounts.sandbox 或 accounts.live，按该组券商和站点提交一次登录：默认 SimNow 电信2，华安 live 必须指定原生站点“一套”或“二套”；无账户仅选择站点并停留登录窗口。备用账户不参与登录，重连沿用启动时选择。固定版本将“券商名-站点名”合为一个下拉选项，先精确选择并回读，再填写及核对账号；登录输入不进入日志。无法识别的确认或登录提示保留现场，不盲点确认。

账号通过固定原生 ComboBox 编号定位，避免把组合框与其子 Edit 判为两个账号输入；密码同时核对原生编号、Edit 类型及密码样式，填写后回读账号。启动失败的错误码和原因写入受管日志。

登录阶段自动处理“快期隐私政策／隐私政策”“快期用户协议／快期软件使用协议”：同一进程和 GUI 线程内同时核对 #32770、RichEdit20A 正文 7601、IDOK 确认/同意及 IDCANCEL 取消/不同意按钮，通过显示/激活事件及启动窗口读取投递确认消息。同一窗口不重复点击，每个终端会话内所有文档确认合计最多 8 次，启动处理期限受 startup_timeout_seconds 限制；投递次数记录日志。主窗出现且启动弹窗处理完成后才继续身份核对，完成初始化或无账户时关闭这些事件回调的自动确认。它不匹配任何交易确认，业务队列及超时隔离规则保持不变。

“确认结算单”还须核对 owner 属于同一进程、同一 GUI 线程及配置环境的主窗口；直接子按钮 1/2 的文字严格为“确认/取消”，正文 7601 为可见只读 RichEdit20A，确认时窗口与按钮可用。正文在终端线程内通过 EM_GETTEXTLENGTHEX/EM_GETTEXTEX 以 Unicode 读取，长度为 128～524288 个 UTF-16 单元且读取完整，包含“结算单”“客户号”“资金状况”和 `Client ID`。条件全部满足才向该窗口投递 IDOK/BN_CLICKED；不发送通用 Enter，也不调用交易函数。此模板以 SimNow 为核验环境，其他模板不能放宽匹配或盲点确认。

已识别文档的正文或按钮尚未就绪、确认消息尚未处理时，界面基线等待并重新检查，不立即把该窗口判为未知。完成启动的原生命令再次检查待处理文档，清空后才关闭事件回调的自动确认；执行器最终核对无阻塞窗口后才发布就绪。

“保证金监控中心”为可关闭的附属网页窗口。须同时匹配当前终端进程和 GUI 线程、顶层 #32770、精确标题、owner 为配置环境的主窗口、直接子控件 1224 为可见 AtlAxWinLic100、窗口带系统菜单且不存在 IDOK/IDCANCEL 按钮。全部满足才向该窗口异步投递 WM_CLOSE；不依赖网页是否空白或加载成功，不发送通用 Enter/Esc，不匹配交易确认。关闭与文档确认共享每终端会话最多 8 次预算，同一窗口不重复投递，并记录关闭请求。

关闭完成以窗口不再可见且主窗口基线正常为准，不要求句柄销毁。快期可以缓存并复用该窗口；扫描观察到隐藏后清除本轮去重标记，再次显示时可重新匹配关闭，仍受会话总预算限制。

成交结果通知精确匹配“成交通知”或“(i/n) 成交通知”（1≤i≤n≤2147483647），同样要求当前进程、GUI 线程、顶层 #32770 和配置主窗口 owner。直接子控件须为：1/确定 Button，1299/不再提示成交通知的 owner-draw Button，7501/Static 正文，1245/上一条和 1246/下一条 Button；禁止 IDCANCEL。正文只检查合约、买卖、开平、成交量、成交价字段标记，不记录明细。空正文有界等待，其他不匹配窗口不操作。

通知处理先检查 BM_GETCHECK：未勾选只投递一次复选框 BM_CLICK，后续扫描回读 BST_CHECKED 后才向该通知投递确定按钮消息；已有勾选不反向切换。勾选无效不重复点击、不提前确认，按步骤期限报错。每轮通知两步共享一个处理预算，观察到隐藏/销毁后清除本轮状态，缓存句柄再次显示可重新处理。trade_notice 日志依次记录 checkbox_submitted、checkbox_verified、confirmation_submitted 和 end；已勾选时省略 checkbox_submitted。通知只是已有成交结果的展示，不作为 API 提交或成交成功判据。

结算单、附属网页和成交通知可以在启动完成后到达，因此执行器在登录等待、启动完成和基线检查中通过 managed_windows 显式扫描；复用现有空闲探测、请求前后核对及显式 resume，不增加后台点击线程。运行期扫描前按现有流程核对会话和账户，并持有唯一 GUI 执行权，只处理上述已验证模板。普通窗口读取和异步显示/激活事件不操作它们；pause 成功后调度器不再探测或派发，因此人工接管期间不会自动点击。

启动等待使用剩余启动期限，运行期等待使用 step_timeout_ms；未知窗口、超时或次数耗尽仍保留失败现场，不重登、不无限重试。日志中的 document_confirmation/submitted 表示已投递请求，document_confirmation/end 表示窗口关闭且界面基线恢复；启动完成还须 login_ready。不记录结算正文、客户号或金额。

“快速配置向导”同时核对取消、下一步、完成按钮及固定 ActiveX 页面控件，使用取消跳过向导，保留默认界面设置；计入同一次数预算并记录日志。启动期间的窗口快照和完成检查使用剩余启动时限，允许客户端完成初始化及连续启动弹窗；初始化结束后恢复 step_timeout_ms 的业务步骤超时，不放宽交易调用期限。

初始化时登录框关闭、主窗标题尚未设置的短暂空档，在启动期限内等待同一进程、同一 GUI 线程的受控窗口；不更换目标进程或线程。原生调用失败记录动作名与错误码，不记录含凭证的完整命令。

主窗出现后仍在剩余启动时限内等待真实 User_Id、交易和行情连接就绪，再建立账户绑定；不把初始化中的空对象或尚未连接判作永久登录失败。等待只读客户端状态，不重复提交登录；期间登录代次改变时拒绝绑定。

每次请求前后检查真实 User_Id、交易/行情内部连接文字以及终端交易日、front/session 标识。数据来源是客户端维护的对象与连接文字，不能由配置非空、窗口标题、星标颜色或自然日推导就绪。

仅从程序自行启动的登录窗口建立账户绑定，不接管未知已有登录。原生 hook 监视登录窗口显示/激活代次；初次受控登录之后再出现登录窗口，旧身份授权失效，必须重启容器。不能仅凭 GetUser 仍能找到旧缓存恢复人工重登后的会话。原生主窗匹配包含受控券商名和指定站点，两种环境继续使用相同的程序/DLL 哈希校验。

观察到真实交易或行情断线时旧绑定失效，停止派发并记为 CONNECTION_LOST。账号不符、原生对象不可读、人工重登代次变化及未知会话变化仍需人工核对，不能仅凭旧缓存恢复。标的查找未命中时进一步核对原生资料列表是否为空，资料未加载与参数不匹配分别报错。

资金来源固定为详情服务器列，不使用内部资金 getters、不混合本地演算值。基础权益、可用资金、占用保证金必须完整；其他可选值缺失为 null。品种状态规则见 [trading_status.md](trading_status.md)。

基线要求当前配置环境的唯一主窗、无未知阻塞弹窗/菜单。使用过键盘的流程释放修饰键，已知资金窗口用 Esc 关闭；纯后台 CSV 不强制复位页面，原生交易状态完全不切页、不按键、不固定 sleep。界面复位失败保留已知提交状态，停止派发。

`just pause` 先停止新派发和新重连，等待当前执行权退出，并检查执行器明确报告的所有权状态；未确认退出时报错，不能人工抢占。`just resume` 对已知连接故障恢复重连计划，其他情况经唯一执行器再次核对，不自动补单。VNC 观看不要求暂停，人工输入必须在 pause 成功之后。

## 自动恢复连接

登录期间精确读取原生登录窗口内可见 Static 控件的“连接服务器失败”，记为 CONNECTION_FAILED 并提前结束尝试；不读取像素或输入框，不把模糊文字和任意超时当作连接故障。密码错误、账号锁定、验证码等可识别提示记为 LOGIN_REQUIRES_ATTENTION；其他未知窗口或原因不明超时停止自动恢复，保留必要截图。主窗已出现但真实连接在剩余启动期限内未就绪，也可按连接故障处理。

默认失败结束后等 600 秒，再由唯一调度线程取得执行权：关闭旧控制器与 worker，确认旧 worker 退出，停止专属 wineserver 并等待其退出，再引导 Wine、启动固定终端和新 worker。IPC 使用新代次，清除旧内存绑定；重新核对账户、连接、会话、GUI 及已支持文档确认后才发布就绪。HTTP 与桌面诊断持续运行，不改变账户、环境或站点。任一步退出无法确认就停止，不能同时运行新旧 owner。

配置及状态字段见 [bootstrap.md](bootstrap.md)。只保留一个计划，失败后重新计时；调用 API 不触发登录或推迟期限。休盘且连接有效不重连，断线不能用来判定休盘。没有账号、关闭重连、暂停或停止时不自动尝试；凭证错误、未知 GUI、所有权不明、存储故障和未决交易阻止自动恢复。自动重连不覆盖所有服务/客户端异常。

断线后立即清退未开始的队列项并记录未执行；已开始操作先保存 submitted/rejected/unknown 事实，不能重放。暂停不丢失恢复期限，解除暂停时期限已过可以开始一次尝试。每次记录失败、开始/结束、耗时与下次时间；等待不刷屏，普通连接失败不截图。日志和必要截图沿用既有容量治理。

## 返回事实与防重发

本地预埋单变为“已发送”才确认提交，不以按键进程成功替代。快速快照没有订单号时保持 null，不凭相似价格、时间或手数认领；没有即时柜台回报不阻塞下一请求。调用方后续独立查询订单、成交及持仓。

查询不等于下单确认，submitted 不等于柜台接受或成交。明确本地拒绝为 rejected；导入或发送影响无法确认时为 unknown。已知提交后的收尾/存储错误保留 submitted，未知请求不自动重发。

SQLite 位于 /data/state/operations.sqlite3，事务在导入和发送前持久化阶段；环境/券商/账户共同形成命名空间，幂等键摘要、参数指纹和响应有唯一真值，不保存密码。恢复和未决计数只针对当前命名空间。相同键和参数重放原 request_id/响应，变更参数 409，正在运行 409，无键同参数仍为不同请求。

正常已结束记录默认保护 168 小时；unknown 不自动过期。数据库及 WAL 默认 128 MiB，checkpoint、回收和事务共用锁；预算不足拒绝新副作用。重启恢复中断记录为明确的未执行或 unknown，保留已知提交事实，不补发。存在 unknown 时初始暂停，人工核对后可恢复独立请求。

## 日志、容量及验证边界

步骤日志包含编号、动作、阶段、事件、结果及耗时；正常步骤记录 start/end，异常记录 error。业务参数不含凭证；不记录整段原生窗口树或登录按键输入。

工件共用 [bootstrap.md](bootstrap.md) 的 300 MiB 容量治理。成功 CSV 在解析和状态登记后删除；失败资料按容量淘汰，未知提交或仍在使用的文件受保护。只有 GUI 卡住、未知弹窗或复位失败等需要视觉证据时截图，原生状态成功不生成 CSV 或截图。

主要检查入口为 just check；少量离线 pytest 验证基本配置、诊断、初始化身份等待与防重发持久化契约。原生 helper 由 just build 编译。历史探针耗时不包含正式日志、SQLite、排队和 HTTP，不能当作新接口性能。在线验证分别覆盖自动登录、非空查询、真实开平仓、撤单确认、重连及交易状态切换；只读登录和查询成功不证明交易闭环，实盘交易验证须用户明确授权。
