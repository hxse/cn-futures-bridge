# 快期2 SimNow 终端能力与实测边界

## 适用范围

本文定义当前固定版本适配可依据的终端能力、读取路径与验证边界。资金、非空表格查询、买入开仓、撤单、对价平仓、原生交易状态读取及无对话框 CSV 导入导出依据 2026-09-21 的 Wine 11.0 复测；报价表数字快速键、六种买卖开平组合的键盘填参、合约资料、其他预埋单/本地条件管理、日志及旧耗时仍依据 2026-09-20 的 Wine 8.0 基线。

当前镜像的 Wine 锁定版本以 [bootstrap.md](bootstrap.md) 为准。保留的历史能力不表示已在 Wine 11 上全部重测，不同环境和操作链路的耗时不能直接归因于 Wine 版本差异。

正式代码仍只提供启动、诊断和截图接口，见 [bootstrap.md](bootstrap.md)。下文的登录、填单、导出、条件单和原生交易状态读取由独立调试探针完成，尚未接入正式 REST 业务接口；不能据此将 `login_state`、`trading_ready` 或 `automation_enabled` 的现有实现解释为业务状态检测。

| 项目 | 实测环境 |
| --- | --- |
| 客户端 | 普通快期2，`2.93.405.1998`；安装包及哈希由 `terminal.lock.toml` 固定 |
| 账户环境 | SimNow，上期技术 / 9999；Wine 11 复测为“电信2”，Wine 8 基线为“全天站点” |
| 容器 | Podman，Debian bookworm-slim，带 VNC 的镜像变体 |
| Windows 运行环境 | 32 位 WineHQ 11.0，包版本 `11.0.0.0~bookworm-1`；历史基线为 Wine 8.0；文泉驿微米黑字体 |
| 桌面 | Xvfb、Openbox，1280×800，24 位色深，DPI 96；Wine 11 复测窗口未最大化，Wine 8 基线最大化 |
| 操作方式 | `xdotool` 按键；原生控件定位及文本读取；原生 CSV 导入导出及普通弹窗对照；交易状态直接查询快期内部函数 |

原生 SimNow 登录、行情显示、拒单，以及有资金时的挂单、撤单、开平成交均有业务样本。尚未验证华安实盘、其他客户端版本或纯 headless 变体的同等交易能力。性能样本未按 VNC 是否有人连接分组，也未隔离宿主机负载，不能外推为生产时延承诺。

“填参验证”表示确认窗口中的参数与输入一致；“本地状态验证”表示导出数据及界面证明本地记录已变化；“柜台反馈验证”表示发出的模拟委托取得业务反馈。三者不能互相替代，弹出确认窗口不等于已经报单或成交。

## 能力覆盖

| 能力 | 已验证内容 | 当前边界 |
| --- | --- | --- |
| 合约、手数、限价 | 小键盘 `+` 定位合约框；Wine 11 下 RM701、1 手、指定限价已发送；Wine 8 有 2 手填参样本 | 2 手只填写并取消，未发送；未覆盖所有品种的价格与数量限制 |
| 买卖与开平 | Wine 11 已完成 RM701 买入开仓 1 手、卖出平仓 1 手；Wine 8 的 6 种买卖开平组合确认参数匹配 | 卖出开仓、买入平仓、显式平今及今昨仓分配未取得成功成交样本 |
| 报价表快速买卖 | `1/3/4/6` 触发对应方向和价格的报单确认，覆盖测试样本均核对后取消 | 默认自动开平、默认手数，不能直接替代明确的业务参数 |
| 报价表只填单 | `7/9` 将买卖参数填入下单板，焦点到价格；可继续修改或触发确认 | 仍使用快捷键配置中的自动开平与默认手数 |
| 资金与账户保证金 | 原生文本及剪贴板均可读取权益、可用资金、占用/冻结保证金、冻结手续费和手续费；已有非零资金样本，并核对挂单、撤单、持仓、平仓后的变化 | 服务器值与本地值须区分；读取显示值不等于强制刷新柜台数据 |
| 持仓、成交、委托 | 普通导出已覆盖非空持仓、挂单、全部订单和本账户逐笔成交；无对话框原生导出已覆盖非空订单/成交及空持仓/挂单 | 无对话框路径尚未验证非空持仓/活动挂单；部分成交、大表完整性和数据新鲜度未完成验证 |
| 合约资料 | 合约表可导出；取得包含 17002 条记录的样本 | 不能把合约表打开或默认“点击查询”字样当作已查询该合约保证金、手续费 |
| 手动预埋单 | Wine 11 无弹窗单条/批量导入、回读及删除；原生结果可直接捕获成功数量与错误；`Alt+Q` 立即发出已有柜台反馈 | 发出样本因资金不足或非交易时段被拒绝；导入只生成本地记录，不能等同于柜台接受 |
| 本地价格条件 | 两种价格方向的条件可建立、导出、暂停、删除；其中一条验证了再次启动 | 未验证触发行情后的真实委托、成交、持仓保护数量及 OCO 互斥 |
| 撤单与快捷平仓 | `F6 → Delete → 确认` 已撤销活动挂单；`F3 → Alt+W → 确认` 已对价平掉真实模拟持仓 | 全撤、改单、市价平仓和反手尚无成功业务样本 |
| 开市/非交易状态 | 原生查询已取得 RM 等品种、RM701 等合约及六个交易所的收盘值；未知标的返回空 | 私有接口依赖固定版本；开盘切换、夜盘品种差异及断线重连刷新尚未验证，见 [trading_status.md](trading_status.md) |
| 异常处理 | 零手本地拒绝、资金不足柜台拒绝、取消确认、资金详情关闭已有样本 | 原生日志覆盖不完整；断线、重连和提交结果未知的恢复未验证 |

全项目的高性能与可靠性要求、操作优先级统一由 [project_principles.md](project_principles.md) 定义，无弹窗 CSV 主链是第一优先方案。下文保留纯键盘交易等路径的真实验证证据；具体能力仍须补齐对应业务验证，这些能力尚未接入正式 REST 业务接口。

## 已验证的键盘上下文

### 页面与下单板

| 所在位置 | 按键 | 本版本观察结果 |
| --- | --- | --- |
| 主界面 | `F1` | 行情报价表 |
| 主界面 | `F3` / `F4` | 持仓 / 成交记录 |
| 主界面 | `F5` / `F6` | 全部委托 / 未成交单 |
| 主界面 | `F7` / `F8` | 合约资料 / 预埋条件单 |
| 主界面 | 小键盘 `+`，即 `KP_Add` | 标准下单板的合约输入框 |
| 下单板 | `Tab` | 在输入项间切换；已验证循环未覆盖“预埋/条件”按钮 |
| 买卖方向输入项 | `1` / `3` | 买入 / 卖出 |
| 开平输入项 | `1` / `2` / `3` | 开仓 / 平今 / 平仓 |
| 价格输入项 | `Home` → `Shift+End` | 选中完整价格，再输入指定值 |
| 下单按钮已取得焦点 | `Space`；历史基线也验证过 `Enter` | Wine 11 成功发送链路使用 `Space` 弹出确认；确认出现不等于已发送 |

部分旧手册将 `F2` 写为未成交单入口；本次固定版本中 `F2` 是期权报价表，未成交单用 `F6`。适配以实际版本和焦点为准。

已验证的完整填单示例，按键与文本分步执行：

```text
F6 → 小键盘 + → Ctrl+A → 输入 RM701 → Tab
1（买入）→ Tab → 1（开仓）→ Tab
Ctrl+A → 输入 1（手数）→ Tab
Home → Shift+End → 输入 2352（限价）→ Tab → Space
```

取得的原生确认标题为：

```text
确认下单: 价格 2352, 开仓 买　 RM701 1手
```

探针核对价格、开平、买卖、合约和数量后，在确认窗口内按 `Enter` 才提交；只验证填参时用 `Esc` 取消。上例在 Wine 11 模拟盘实际成交价为 2347，示例价格不是今后的下单建议。不能仅凭按键发送成功或确认框消失返回业务成功。

价格框中 `Ctrl+A` 曾未选中全部旧值，直接输入产生过拼接价格；改用 `Home → Shift+End` 后通过回读验证。Wine 8 基线中上下方向键在标准下单板用于导航，`Up` 没有把 2345 改为 2346，不能按“加减一跳”使用。

### 报价表快速键（Wine 8 历史能力）

本次实例的“启用键盘快速下单”原先关闭，仅在测试这些数字快捷键时临时打开，结束后恢复关闭。该观察不是出厂默认值保证。标准下单板的键盘填参不依赖此开关。

| 报价表内按键 | 买卖及价格 | 动作 |
| --- | --- | --- |
| `1` | 买入，卖一价 | 弹出报单确认 |
| `3` | 卖出，买一价 | 弹出报单确认 |
| `4` | 买入，买一价 | 弹出报单确认 |
| `6` | 卖出，卖一价 | 弹出报单确认 |
| `7` | 买入，卖一价 | 只填单，焦点到价格 |
| `9` | 卖出，买一价 | 只填单，焦点到价格 |

这些配置的开平为“自动”，确认标题也显示“自动”。RM701 的样本数量为默认 1 手；不能推断手工改过下单板数量后，报价表数字快捷键就会使用该数量。需要明确开平、手数、限价的业务仍须逐项设置并校验。

## 查询、导出与必要的界面定位

### 资金详情

资金详情尚未验证可用的 CSV 或纯快捷键读取路径，当前按 GUI 层方式处理：确认主窗口身份，通过原生控件定位资金区“查询(Q)”按钮并取得焦点，按 `Space`，读取“期货资金账户详情”的原生文本，解析后用 `Esc` 关闭。固定版本样本中按钮 ID 为 `3009`，文本框 ID 为 `7201`；使用 `WM_GETTEXT` 读取，不需要 OCR。这是 GUI 控件操作，不是客户端提供的业务 API。

原生菜单命令也能打开详情，但本轮完整耗时未优于按钮定位加空格。`F6 → Alt+Q` 未打开窗口；`F10`、`Alt+F` 未形成可靠的纯键盘直达链路，且 `Alt+F` 在订单页会选择“已撤单/错单”。尚未确认全局资金详情快捷键。

一次读取覆盖静态权益、动态权益、可用资金、占用保证金、冻结保证金、冻结手续费和手续费，保留服务器与本地两列。服务器值与客户端计算值实测可不同；不得混用、覆盖或把读取完成时间当成柜台数据更新时间。[官方资金说明](https://doc.shinnytech.com/q72/latest/9.html)区分了这两种来源。

剪贴板为已验证的较慢备选：先确认文本框焦点，再 `Ctrl+A → Ctrl+C`。详情窗口可能保留上次焦点，不能每次盲按 `Shift+Tab`；剪贴板可能短暂被占用，未取得本轮有效内容不能返回旧数据。

### 订单、持仓和成交表格

以下快捷键用于首次定位表格、设置筛选及核对历史样本；有效绑定后的重复导出直接调用原生入口，不需要每次切页或取得焦点。

| 查询 | 已验证的页面、筛选与焦点恢复 | 非空 CSV 可读内容 |
| --- | --- | --- |
| 活动挂单 | `F6` | 报单编号、合约、买卖、开平、报单/未成交手数、价格、时间 |
| 全部订单 | `F5 → Alt+A → F5` | 报单编号、挂单状态、详细状态、报单/成交/未成交手数、成交均价、时间、交易所 |
| 汇总持仓 | `F3 → Alt+S → F3` | 总持仓、今仓、昨仓、可平量、持仓均价、实收保证金、盈亏、交易所 |
| 本账户逐笔成交 | `F4 → Alt+D → F4` | 成交编号、合约、买卖、开平、成交价格/手数、手续费、平仓盈亏、时间、交易所 |

历史普通导出流程是：筛选后再次按页面功能键使表格取得焦点，再选择记录、右键打开菜单、用键盘选择“导出列表”并保存。当前业务导出改用下文的无对话框链路，CSV 仍按 GB18030 解析。账户成交明细不是全市场逐笔行情；全部订单中的“已撤单”样本仍可有非零未成交手数，必须结合状态判断活动挂单，不能仅按剩余数量过滤。

普通导出的菜单位置不同：未成交表的最后一项是“导出为条件单”，“导出列表”在它上方；持仓表在导出之后还有其他业务操作。不能统一使用 `End → Enter`。另存为窗口确实存在，可用 `Alt+N → Ctrl+A` 输入完整 Windows 路径；其打开、填路径、写入和解析均计入查询耗时。

有效数据须来自本轮独立导出文件，并核对页面、筛选、列、合约和记录完整性；不能把旧文件或只有表头的文件当作成功的非空查询。少量样本的行数核对不能替代大表完整性验证。

已观察到的入口限制：

- Wine 11 非空挂单和成交表中 `Ctrl+C`、`Ctrl+Insert` 未复制出内容，`Shift+F10`、菜单键未打开上下文菜单；因此历史普通导出需要右键定位，无对话框原生导出不依赖该菜单。
- 标准列表消息和可访问性接口在已有 3 条订单、2 条成交的表格上仍返回零行或零个子对象，未取得单元格数据。不能用此返回值判定空表，也不能宣称原生表格读取已替代导出。
- 标准下单板的 `Tab` 循环未进入“预埋/条件”按钮；条件设置的入口及部分字段仍使用鼠标定位，尚无稳定的全键盘创建链路。
- GUI 中空持仓或空未成交表未提供与非空表相同的菜单导出入口；原生路径已有空表成功样本，但仍不能将菜单入口缺失解释为查询成功。
- 普通导入会出现文件选择和结果确认窗口；下文的无弹窗导入均跳过创建，但本地记录生成仍不能等同于下单发送。
- 预埋单普通菜单导出的历史样本只覆盖选中的可导出记录；无弹窗原生导出已回读多条未启动记录和一条已发送记录。仍须核对筛选与完整性，不能用本地记录数代替柜台委托数。

这些是当前 Wine、布局和焦点下的实测限制，不能外推为其他版本没有相应键盘能力。

### 无对话框原生 CSV 导出（统一方式）

后续所有业务 CSV 导出均使用“核对并绑定目标表格 → 在快期 GUI 线程向原生导出入口传入完整路径 → 快期写出 CSV → 读取并校验本次文件”的链路。保留快期原生的列、编码和数据格式；流程不创建保存或覆盖确认对话框，隐藏窗口或弹出后自动确认不算满足本约定。

有效的表格绑定可以复用，以减少页面切换、焦点等待和菜单操作；客户端重启、对象重建或布局变化导致绑定失效时，须重新定位并核对。无弹窗入口不匹配、绑定失败、导出失败或内容校验失败时明确报错，不能自动退回普通弹窗导出，也不能使用旧 CSV 或零值掩盖错误。普通导出只保留为历史证据或显式诊断对照，不再作为业务主路径或自动回退。

当前固定版本的 `ExportCSV` 内部处理支持非空文件路径参数。独立 32 位调试模块在快期 GUI 线程调用该处理，快期原来的代码直接写 CSV，跳过 `GetSaveFileNameA`，没有创建保存窗口；未修改磁盘上的快期程序，也未接触 CTP 登录或交易协议。

适配绑定真实的表格窗口及内部对象，检查主程序 SHA256、32 位映像、函数特征、SimNow 窗口身份、对象所属窗口与列数量。本轮通过 ANSI 窗口接口取得对象；Wine 下 Unicode 接口返回的过程句柄不能直接当作对象指针。该路径依赖私有对象布局与调用约定，固定版本以外不可复用，仍未提供正式外部调用契约。

正确性经验与验证边界：

- 3 条订单、2 条成交在各 20 次普通/无对话框对照中，CSV 逐字节一致，覆盖列、编码、合约、买卖、开平、数量、价格、订单状态、手续费等内容；已绑定表格的独立重复采样也保持一致。
- 窗口创建观察器在普通导出中每次观察到 2 个对话框类窗口，在无对话框导出中为 0；这是跳过创建，不是隐藏窗口或弹出后自动确认。
- 表格完成绑定后可以省略页面切换；另在焦点位于行情页、订单页隐藏时分别导出订单和成交，各 3 次内容一致且焦点未改变。对象重建、布局变化后仍需重新绑定。

逐字节对照证明的是同一受控数据下两种导出方式的等价性，日常查询不再额外执行一次弹窗导出作对照。每次查询仍须使用新文件名，确认原生调用成功、文件生成完成、表头及记录范围有效；账户数据发生变化时，应读取新快照，不能要求它与上一份 CSV 相同。

该导出对照未建立新仓位或挂单，原生路径的非空持仓/活动挂单、客户端重启、长时间运行和大数据量尚未验证；其他表格也须沿同一无弹窗路径补齐验证后才能声明支持。统一选型不扩大已验证范围。标准控件/可访问性接口无法读取表格的旧结论仍有效；本路径调用的是快期自己的 CSV 写出逻辑。
