# 实盘环境与单账户绑定

## 使用场景与设计初衷

用户使用华安期货 CTP 账户，希望自己通过 CFB 在实盘查询及交易。此前“只能查余额和持仓、别下单”限制的是 AI 在未获授权时进行实盘交易测试，不是产品权限；本任务不设置实盘强制只读或 read_only 开关。

一个 CFB 实例只管理一个账户和一个终端会话。请求中的 mode 应验证当前会话环境，不能用作动态选择账户、自动切换环境或启动第二个终端的指令。

## 方案对比

为 sandbox/live 各开一个端口会引入两套会话和资源管理，超出本项目的单账户定位。固定启动环境、保留共同路由和队列，能让环境错误在副作用前明确返回。

现有锁定的官方快期2安装包已包含上期技术 9999 以及 H华安期货 6020。华安原生站点为“一套”“二套”。分别生成只包含目标券商的受控终端种子，可继续使用原主程序及核心 DLL 哈希，不移植或改写认证参数。

## 取舍结论

启动时由 TOML 确定环境、券商、站点和账户；运行期间不可通过 API 改变。终端和 Wine 数据按环境、券商、站点、账户隔离，旧目录保留但不自动导入旧预埋单。所有已支持能力沿用同一执行链路；尚未核验的市价/IOC/FOK 等限制保持独立于环境。

默认使用离线校验、原生编译及无账户断网启动验证。用户填写实盘配置并明确授权后，通过重建重启入口进行登录及账户只读查询；AI 不执行实盘报单、平仓、撤单、预埋单写入测试，交易由用户控制。先完成构建再停止旧容器，避免构建失败导致现有服务中断。

隐私政策和软件使用协议属于用户已授权自动处理的启动步骤。用已识别窗口及控件的原生事件确认，能够处理阻塞窗口读取的首次弹窗，同时让交易确认继续归属各自业务流程。
