# 路由性能测量与优化

## 任务边界

交付八个业务路由的优化前后性能测量，以及经数据和正确性验证的公共日志、CSV 读取、资金窗口、下单板定向读取和请求内表格定位优化。实现与受影响 current spec/用户说明同步；实际测量结果只在回复提供，临时探针及数据放忽略的 debug 目录并在结束后清理。

路由数量、路径、方法、参数、响应结构和提交/未知/观察语义保持不变。保留单账户 FIFO、GUI 前后检查与有界恢复、完整身份、报单引用和交易所编号关联、参数核对、幂等持久化、必要 CSV 一致性核对、工件容量及活动文件保护。不得用缓存业务数据替代新快照，不提前释放执行权或后台补发交易。

不强行实现风险或收益不合适的候选；不扩展 FOK、平今/平昨或实盘验收。停止线是完成所有具备条件路由的同口径测量、必要验证和本次模拟副作用清理。未就绪、休盘、未知提交等限制如实报告，不把失败延迟当成功性能。

## 任务规范

### 测量与对照

优化前后保持相同站点、合约、手数、主要参数、确认轮数及等待间隔。HTTP 从发起到完整响应结束计时，并用 request_id 关联服务端总耗时、FIFO 排队和步骤日志；嵌套步骤不重复加总。每个查询至少 5 个顺序样本，模拟市价开仓/平仓和限价挂单/撤单各以 1 手完成至少 2 次闭环，报告样本数、均值、中位数、范围及错误，少量样本不声称长期 P95。

线上测量是用户明确授权的独立 SimNow 调试，不放入默认 pytest。每次写操作前核对 environment=simnow、mode=sandbox、BrokerID=9999、指定站点、服务就绪及品种正在交易；为每次新指令使用唯一幂等键。优先选择已有能力验证的普通期货合约，禁止实盘报单、平仓、撤单。只清理本次精确关联的订单与仓位，遇到未知结果先按返回身份有限查询，禁止换键重发；明显异常停止相关写操作。

### 日志与容量

所有阶段日志、脱敏和容量配置保留。日志写入继续在原跨进程锁内核算实际总量和单文件大小；只枚举已登记的日志路径与大小，健康预算不扫描 /proc。确需删除时才读取活动句柄并按既有规则淘汰最旧可删除日志，活动终端日志不删除/截断，无法腾出预算仍标记存储不可用。周期维护继续检查活动文件增长和单文件上限。

拆分日志目录收集与活动句柄分类，所有调用使用同一规则，不产生第二份日志真值。新增/删除/轮转文件、其他日志进程写入和终端自行增长必须纳入预算，不以时间缓存或丢日志换性能。若目录扫描仍成为已测瓶颈，再在本范围内评估增量方案；未证明需要时不引入持久化账本。

### 必要快照与资金窗口

写操作前只读取仍用于返回和核对的持仓；删除未被后续逻辑使用的前置委托、成交读取。新订单提交后保留精确订单、对应成交和持仓快照，撤单后保留目标订单及持仓，省去没有归属用途的成交表。所有读取使用本轮新文件，读取失败仍报错；持仓差值不用于认领订单。

表格在一次请求内复用已核验的窗口绑定，每次复用重新核对主窗/进程/线程、控件编号、父窗口、原生对象和过程、列布局及筛选状态；不符时丢弃绑定，执行完整定位再使用。绑定不跨请求、重连或人工恢复保留，异常收尾也清空。目标选择前后的精确身份与参数回读不能省略，两次 CSV 查询的一致性比较及默认轮间等待保留。订单、成交、持仓、资金与交易状态不得用缓存值代替新快照。

资金窗口出现时保留该次完整控件快照直接读取服务器列，省去重复枚举；读取完成后复用已有轻量就绪检查、精确 WM_CLOSE 模板及关闭回读。未知窗口仍阻断，不将未关闭的资金窗口留给后续请求。交易状态查询保留当前原生状态与前后会话校验。

### 下单板定向读取

模拟市价继续使用涨跌停限价＋IOC，显式 IOC 共用同一路径。下单板定向读取只返回已绑定主窗、标准下单板及固定字段；初次定位仍要求唯一预埋按钮和正确层级。请求内可记住面板句柄，每次读取验证所属进程/线程、主窗、标准控件和可用状态，失效后只允许重新定位，不缓存字段值。

填写合约、手数、价格仍通过原有控件赋值及 Tab 提交，买卖/开平仍通过原有焦点和快捷键；每次提交编辑后的回读、最终完整表单核对、只在恢复阶段跳过相同文字、合约切换后重读后续字段全部保留。菜单设置及恢复仍沿用原流程，不为减少时间改成 GFD 或跳过恢复。

原生表格选择已在同一调用核对唯一选中数、索引及焦点，Python 不再额外枚举全部窗口只为再次读取焦点。选择前后 CSV 身份核对、导出后的必要重新选择均保留。新增原生只读命令与 Python 同镜像更新协议；不增加内部交易入口，不热换运行中的 helper。

市价及显式 IOC 的菜单等待保留首次观察到菜单的完整结果，用于唯一性和内容核对，不立即重复枚举；选择后仍以新窗口快照确认菜单消失，并回读有效期文字。已经观察到关闭时，finally 不再重复枚举；选择、等待或核对中断且尚未确认关闭时，仍重新检查本次菜单并按原有规则退出。出现多个菜单、菜单内容或可用性不符、关闭超时仍沿用原错误，不直接调用菜单命令代替已核验按键。

预埋设置窗口使用等待阶段首次观察到窗口的完整快照核对标题与 owner，省去紧接着的相同读取；确认手动选项、摘要和确定按钮时仍读取新快照，不能沿用窗口出现时的旧参数。买卖/开平选项若本次实时读取已经选中且标签正确，不再立即重复回读；发生点击时必须重新核对，填参与恢复结束仍完整核对全部字段。不跳过文本编辑的 Tab 提交、CSV/原生参数检查或同步收尾。

### 限价提交的重复读取与诊断

GFD 导入或 IOC 创建后，刚完成参数核对的预埋表作为本次首次选择的候选定位依据，直接交给共用发送链路，不在选择之前再导出相同表格。选择之后必须重新导出，核对唯一身份、完整行及索引未改变，再重新选择并发送。候选快照不用于柜台订单确认，不跨请求保留；候选失效、重复、移位或参数变化时停止发送，不猜测目标。清理仍独立读取当前预埋表并执行选择前后核对，不沿用发送前的旧表。

按请求汇总原生命令的调用数和总耗时，包含通信与结果处理；只记录命令名，不记录含账号的参数。汇总在请求收尾后输出，计量在下一请求前清空，不更改失败、超时及执行权语义。日志用于区分 CSV 原生执行、重复定位和外围调用，不通过关闭日志换性能。

根据同口径分段测量评估合并原生读取、SQLite 连接及 checkpoint、工件计量；没有足够收益则保留原实现，不削弱发送前持久化、容量核算或活动文件保护。

## 公开接口与用户写法

八个 /cfb 路由、配置写法与返回字段保持不变。用户继续通过 order_id 或完整 identity 调用 fetch_orders 确认状态；HTTP 202、submitted、observed 和 stable 的含义不改变。

例如 `GET /cfb/fetch_positions?mode=sandbox&exchange_id=DCE&instrument_id=m2701` 仍取得新 CSV 快照并返回 consistency；`POST /cfb/create_market_order` 仍接受 mode、exchange_id、instrument_id、side、offset、volume，返回真实 identity/order_id 及既有 verification。优化不要求客户端改参数或轮询方式。

## 测试、验证与阶段过渡

必须通过 just check、just test、just build；正式检查与在线性能探针保持独立。原生定向读取及表格绑定通过独立无网络 Wine 窗口夹具，核对正常层级、实时字段变化、失效/错误窗口、对象及列布局变化、筛选变化；Python 离线检查覆盖失效重定位和请求结束清空。

日志离线检查覆盖正常写入无句柄遍历、轮转、多个 writer 共享预算、终端文件增长、阈值清理与活动文件保护、容量不足和写入失败。CSV 检查证明省去无用表格但保留持仓/订单/成交事实及所有错误语义。资金窗口检查证明正文来自本次打开快照，并由已有精确模板关闭和回读；沿用未知窗口阻断、恢复期限及仅投递一次的反向检查，再用正式余额路由在线核验。

限价定位检查覆盖复用候选后仍读取新 CSV、行移位、重复身份、参数变化及读取失败时均不发送；清理继续使用独立新快照。原生命令计量不得泄露参数或改变异常。限价优化在线对照分别测量 GFD 开仓和持仓内平仓的挂单/撤单各两轮，必要时用既有模拟市价建立并清理本次一手仓位；公共调用改变时复测八个路由。

市价重复读取优化离线覆盖菜单单次出现结果的复用、选择后的新关闭观察和有效期回读、非法或不可用菜单、关闭超时的退出；覆盖预埋窗口出现后摘要改变时拒绝确认，以及已选选项免除重复读、点击未生效时失败。在线至少两轮市价一手开平仓，并回归显式限价 IOC 一手开平仓、GFD 挂单/撤单及五类查询；比较原生命令次数和填写、创建、恢复耗时，区分交易回报等待与界面优化收益。

先取得基线，再实现与离线验证，构建部署后按相同参数复测。若某项优化不能在保持行为下可靠验证则撤回该项，其他有效修改可交付。部署不热换仍在使用的 helper。在线失效须先定位，保留未决状态，不以放宽校验取得成功数字；结束时核对本次持仓和挂单已清理、执行器恢复空闲。
