# 路由性能测量与优化

## 使用场景与设计初衷

单账户调用方需要查询和开平仓有较低延迟。现有完整 HTTP 路径还包含同步日志、目录及进程句柄扫描、重复表格定位和已退出的差集确认留下的 CSV 读取。局部原生命令很快不代表完整请求很快，需先测全部八个路由，再对确定的成本优化。

用户要求合理取舍，保留已经设计好的可靠行为，不为追求数字强行删功能。当前 SimNow 全天站点可用，可在同一配置和一个合约上建立优化前后对照。实盘不参与交易验证。

普通限价已经使用无弹窗 CSV 导入，仍需定位、发送、确认和清理。导入后的参数快照与紧接着的候选定位读取重复，应复用同一次已核验结果作定位依据，并保留选中后的新 CSV 核对；不能把省去重复读取扩大为按旧快照直接发送。

市价模拟与显式 IOC 共用下单板，CSV 候选复用同样适用。菜单和预埋窗口等待已取得完整观察结果，再立即读取一次没有增加操作后的证据；可复用该次出现观察。菜单选择、选项点击和预埋参数确认之后的新核对仍有独立作用，不能随重复读取一起删除。

## 方案对比

减少日志、只读一次 CSV、提前释放 GUI 或先回成功再收尾，都会改变诊断或一致性语义，不用于本任务。维护跨进程增量容量账本可以减少目录扫描，但会引入额外恢复与校准成本。

先保留每次容量核算，只把昂贵的进程句柄扫描移到实际删除和周期维护时；再删除后续逻辑不使用的快照，复用资金窗口出现时的完整读取及现有关闭模板。下单板只读取固定字段，表格绑定限定在单次请求内并核对句柄、对象、列布局和筛选，减少重复全窗口读取而不引入跨请求缓存。资金保持服务器控件文字来源，交易状态保持终端原生状态，不引入资金内部 getter 或日历推断。

## 取舍结论

不设未经测量的耗时承诺。按同口径记录完整响应、排队、主要步骤和失败；保留有实际收益且满足原可靠性约束的改动。收益不明确或风险不合适的候选不强行实现，结果在回复中说明。

增加按请求汇总的原生命令耗时，用于判断读取、通信和定位的成本。SQLite 连接与 checkpoint、工件容量计量只在分段测量证明需要时重构，不为少量外围开销削弱持久化和容量治理。
