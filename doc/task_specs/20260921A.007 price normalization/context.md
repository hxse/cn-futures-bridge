# 限价归一化与价格边界

## 使用场景与设计初衷

上游按开盘价乘以 1.05 等方式计算目标限价，可能产生非整跳价格、浮点尾差或略超涨跌停的结果。合约步长及当时的有效价格边界由快期掌握，CFB 应统一负责最后的价格处理，上游保持既有路由和输入。

既有校验严格拒绝非整跳价格，但巨大有限数的十进制取余会抛计算异常，涨跌停缺失时又会跳过该侧检查。需要把输入错误、资料不可用和明确可修正的情况区分开，不把不可靠资料当成没有限制。

## 方案对比

全部拒绝简单，但常见计算需要每个调用方重复处理。无条件四舍五入和裁剪会提高买方最高出价、降低卖方最低售价，也会把单位输错的大数变成有效指令。

采用有界修正：极小尾差吸附到合法价；普通非整跳价格按买下卖上处理；买价稍高于涨停或卖价稍低于跌停时，可在明确幅度内回到边界。相反方向越界和大幅越界拒绝。自动调整仅决定提交前的一次价格，不承担策略追价或重新报单。

## 取舍结论

默认启用分类处理，保留八个路由和请求参数。超界修正比例默认 5%，允许配置；浮点尾差固定为一跳的十亿分之一。真实合约资料仍是价格边界的唯一来源。

幂等按原请求识别，实际执行副本使用调整后的价格。结果、日志及恢复记录保留调价事实，已有提交事实、订单关联、FIFO、CSV 核验和 GUI 收尾继续成立。实盘能力按相同规则运行，AI 写操作验收只用获准的 SimNow。
