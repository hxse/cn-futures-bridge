# 内嵌网页与监控中心窗口

## 使用场景与设计初衷

快期的保证金监控中心使用内嵌浏览器，窗口外层标题可能为空。原自动处理依赖“保证金监控中心”标题，因而漏掉真实窗口，使界面检查阻塞。仅关闭已识别窗口可以恢复操作，但用户同时希望解决网页空白的原因，并让容器重建、重启后仍然有效。

运行环境禁用了 MSHTML，未携带对应 Gecko，已有 Wine 前缀还可能缺少 HTML MIME 和 about 协议注册。启用渲染组件不能依赖手工修改容器或一次性修补数据卷。

## 方案对比

按空标题直接关闭会误处理未知交易确认；读取像素、等待网页文字或标题出现又受网络和渲染速度影响。浏览器控件的 IWebBrowser2 接口可以在页面未加载完成时提供导航网址，结合原有进程、线程、owner 和控件模板形成明确身份。

每个账户启动时在线下载 Gecko 会增加网络依赖和前缀重复内容。构建时验证固定官方包并提取到 Wine 的共享搜索目录，使两个镜像共用同一版本，运行时不需要下载。

## 取舍结论

保留预编译 Wine 和中文字体，启用其内置 MSHTML，携带固定 x86 Gecko，并在每次 Wine 引导后注册 MSHTML，覆盖既有前缀。Mono 继续禁用。

监控中心身份改由原生窗口结构和精确网址共同确定，不依赖外层标题、网页正文或加载完成。处理仍受唯一 GUI 执行权、现有期限和次数预算约束；其他窗口继续按原规则隔离。交易接口、交易结果判断和重连设计不属于此次修改范围。
