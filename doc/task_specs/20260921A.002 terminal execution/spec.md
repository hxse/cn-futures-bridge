# 终端执行器与可靠交易闭环

## 任务边界

实施前完整阅读[主任务](../20260921A%20cfb%20trading%20api/spec.md)及全部扩展，并复用[运行治理前置](../20260921A.001%20container%20operations/spec.md)的日志、配置、工件及容器检查入口。

交付范围为：单一调度器、独立 GUI 执行器及 IPC、固定版本原生 helper、自动登录与就绪、逐路由准备/复位、快速提交与独立查询、原生品种交易状态、CFB 简洁模型及轻量防重发记录，以及内部/模拟验证入口。

正式 helper 的源码、编译和版本校验纳入受控构建；不从 ignored debug 目录加载业务组件，不依赖临时路径中的 DLL 或仍运行的历史控制器。复用已有数据卷排他锁、日志与清理登记，不平行实现第二套 runtime 或存储预算。

本阶段不发布 `/cfb` HTTP 路由，不修改上层代理，不增加实盘、策略、行情或止盈止损范围。内部模型按主任务接口和字段扩展定义，为后续路由复用；不提前创建假的 HTTP 回报。

停止线：唯一链路可快速完成本地限价/撤单提交，再由独立查询验证真实模拟挂单、开平仓及账户变化；全路由排队、幂等复位、有限等待、防重发、原生交易状态和容量治理有对应证据。本轮以 just check 为主要验收入口，真实交易和状态切换的未覆盖范围如实保留，不能把类型检查当作在线验证。发送/撤单目标不唯一、可能自动重发、无法确认调用结束或复位失败却继续派发均阻断交付；未即时取得柜台订单号不是本地 submitted 的阻断。

## 任务规范

### 所有权、排队与取消

调度器拥有有界 FIFO、准入、幂等登记和操作记录；独立执行器是唯一可向终端发动作的进程，原生 helper 归它管理。接口使用经校验的业务参数，不开放任意按键、窗口句柄或文件路径作为外部输入。

八个业务路由每次可执行请求均进入同一有界 FIFO，原生状态查询也不绕开调度；同键结果重放不再次执行。一次本地操作从准备到收尾保持所有权，不等待柜台回报或成交；账户查询、登录及取证不能穿插另一操作。健康及已有诊断状态读取不进入业务队列。

准入时记录期限，队列满立即拒绝；出队前再次核对未过期且未取消。尚未开始的 HTTP 请求取消后移除队列项；取消与开始执行之间必须有唯一状态决策，不能同时报告未执行并派发动作。

执行开始后的 HTTP 取消仅结束等待，执行器仍完成必要的本地核对、收尾及结果记录，不因此增加柜台轮询。操作仍在运行时不可释放所有权或复用 IPC 槽位，等待者退出与底层操作终止不同。

进程通信包含操作编号、执行器会话代次、命令类型及截止信息；迟到的旧代次响应不能完成新请求。IPC 输出、缓存及队列均有界，错误要可定位而非永久等待。

### 登录、健康与人工接管

从受控配置和固定安装包选择 SimNow 上期技术/9999，优先使用已有业务证据的电信2站点；不在失败时自动切换到其他账户、实盘或未经核对的站点。登录前确认实际窗口和字段，输入凭证不得进入按键日志、截图例子或错误正文。

有账户配置时启动尝试一次登录，完成真实账户身份、连接、交易日及必要提示的核对；无配置仅显示登录界面。登录失败保留可诊断状态，不由业务请求触发重试。客户端自行重连后使旧绑定、状态及会话身份失效，重新核对后才能交易。

无法取到可信交易日时可以提供带 null 的已验证查询字段，但写操作保持不就绪。不能用宿主自然日、窗体标题中含“快期”或配置非空证明身份/登录就绪。

健康检查区分进程存在、IPC 活跃、GUI 可响应和业务就绪。GUI 消息超时不证明消息被取消；卡住后停止派发，保留所有权，直到确认旧调用结束或受控终止旧会话。不能在旧 GUI 线程仍可能回调时卸载 DLL、解除共享内存或启动第二个控制器。

pause 先禁止新派发并等待当前本地操作及收尾退出。resume 核对旧调用已终止、身份和界面基线安全后再放行；不自动补单或修复未知交易。正常 submitted 没有成交回报不阻塞队列，unknown 保留防重发标记；界面或所有权仍不明才保持 blocked。

### 每个路由的准备与复位

每个可执行动作定义 prepare、execute、verify、cleanup，持有同一执行权到 cleanup 验证完成；prepare/cleanup 重复调用不得产生交易或改变他人的订单。新请求不依赖上一次输入框内容、默认选中行或遗留的修饰键。

| 路径 | 准备 | 收尾 |
| --- | --- | --- |
| 纯无弹窗 CSV | 核对会话、对象、表头和筛选范围 | 释放/清理本次文件；页面没有改变则不切页 |
| CSV 加快捷键发送、撤单 | 确认目标页面/记录、焦点及完整参数 | 关闭自己打开的已知窗口、释放修饰键，回到已定义主窗口基线并验证 |
| 资金等直接 GUI 操作 | 定位已知窗口和控件，确认来源 | 读取后关闭自己打开的窗口，验证可交权 |
| 原生交易状态 | 核对模块、会话、连接、数据就绪及请求品种身份 | 完成读取与同会话核对，释放本次读取资源；不切页、按键或复位 GUI |

基线只要求主窗口身份、没有阻塞本轮流程的弹窗、键盘状态及后续可定位性明确，不在每次 CSV 请求后强制按 F1。每个键盘/GUI 路径的目标页和安全退出动作须在固定版本验证。已知窗口可以使用已验证的 Esc 关闭；未知窗口不能通过盲按 Esc/Enter 或恢复整套设置来猜测复位。

收尾只清理能够证明属于本轮的本地工件和预埋记录，不能撤销已提交柜台订单、删除其他请求记录或覆盖用户设置。收尾失败记录日志、必要截图并暂停派发；不能在 finally 中无条件解锁让下一动作接管。

### 终端适配

原生 CSV 优先复用已证明的 GUI 线程入口；绑定须校验固定主程序哈希、32 位映像、函数特征、对象与窗口关系、列布局和 SimNow 身份。重启或对象重建后重新绑定，不长期复用裸地址。

导出保留原编码及列语义，使用本轮唯一新文件并校验调用结果、写入完成、表头和记录完整性；绑定有效时可后台读取，不能每次强制切页和打开菜单。输出文件名由受控工件管理器分配，不接受外部任意路径。

导入保留原生字段校验及错误信息，回读核对本次记录。临时接管文件选择/结果提示的作用域必须限制在本次 GUI 线程调用，并恢复原槽位与窗口创建登记；错误、异常和超时路径同样管理生命周期。未知确认内容不能自动点“是”。

发送前检查本次导入记录的唯一身份、未启动状态、合约、买卖、开平、数量、价格和所需交易条件；CSV 字段不能表达的模式先寻找等价快捷键，再寻找可靠 GUI 操作。禁止将普通限价发送后主动撤单包装为 IOC/FOK。

键盘发送、撤单和其他动作均须核对目标页面、焦点及记录身份。多记录情况下不能以 Home/第一行替代匹配；操作者或外部账户活动产生不唯一候选时，停止写操作并报告未知。

读取范围包含全部订单、本账户逐笔成交、终端实际可提供的持仓及资金。输出采用 CFB 自定义必要字段，不强行仿制 CTP 行划分；资金来源不混用。CSV 含中文，沿用 GB18030 与既有字体/映射，已有样本未见乱码或方块，本阶段不另做字体专项。

### 原生交易状态适配

查询链路与公共错误以主任务接口/模型扩展为准，入口和固定文件身份见 [原生状态能力](../../current_specs/trading_status.md)。helper 在已登录快期 GUI 线程内通过已加载核心 DLL 查找品种并调用 Product_Status，返回已核对的身份、原生值及会话代次，由共享模型产生 is_trading。Instrument_Status 仅用于合约适配或验证，Exchange_Status 不替代品种读取；本阶段不增加直接内部报单链路。

初始化时校验主程序与核心 DLL 哈希、32 位架构、所需导出及调用约定；正式适配表纳入受控构建，不能只校验 exe 后接受任意 DLL。常驻控制器复用同一会话，不按请求启动新 Wine 进程或重复加载组件。对象查找失败时不得解引用；GetProductLike 返回的实际身份须精确核对，不把模糊匹配当作请求命中。

连接/会话有效性与原生整数分开维护。执行前确认元数据已加载，读取前后核对会话代次及连接；客户端断线、退出、重启或重连使旧绑定和数据可信标记失效。只有取得新会话数据就绪的证据后才恢复读取，不能用旧对象仍可访问、值未变化或已到开盘时间证明已刷新。

状态查询不修改 GUI，不进行固定 sleep、CSV 导出、页面切换或截图；请求仍持有执行权到读取收尾结束。异常记录原生值、实际品种、会话和失败步骤，必要时才截图。未知编码、缺失标的、未登录、断线、版本不匹配和超时按主任务分别报错，不返回默认休盘，也不自动切到颜色、时间规则或探测订单。

### 订单关联、状态与持久化

共享请求及 CFB 返回模型以主任务扩展实现。提交结果至少区分 submitted、rejected、unknown；未开始副作用的校验/排队错误不装成拒单。查询完成和界面收尾结果独立记录，不能用一个 success bool 表示柜台、成交与界面全部成功。

最小记录包含排队、执行、导入前、参数已核对、提交前、已知本地结果和收尾状态。导入与发送前持久化必要防重发事实，不建立 awaiting_receipt 长等待阶段。查询或纯键盘跳过不适用步骤，但不能跳过自身核对和收尾。

轻量数据库记录 CFB request_id、实际账户/环境、会话代次、指纹、幂等键摘要、关键阶段、已知副作用、原响应及必要证据引用。不保存密码、完整配置或全部原生 CTP 回报，不扩展为自动对账恢复引擎；活跃文件通过前置工件服务管理。

提交路径执行“导入 → 回读参数 → 快捷键发送 → 快速读一次订单 CSV → 收尾”。能证明本地动作完成后即可产生 submitted，不等柜台接受或成交。订单号能可靠取得就填，否则 null；即时明确拒绝返回 rejected，本地影响无法确认才 unknown。单次观察失败不抹掉已知提交事实，调用方可再查询。

发送前及撤单前必须可靠定位本地目标；返回柜台订单号时也不能单凭参数或时间猜测。回报暂时无法关联不阻止已经确定的本地提交返回，保留 null 并交由独立订单/成交查询；不因想填满响应而认领其他订单。复位失败时保留已知提交状态并报告收尾错误。

主任务定义的 Idempotency-Key 通过事务原子登记。相同键内容变化拒绝，仍运行返回进行中，已结束重放原已保存结果；不重复执行导入或发送。没有键的同参数请求仍是不同指令，不以参数去重破坏用户意图。

重启只恢复防重发记录，将中断且影响不明的操作标为 unknown，不自动重放、补单或清空其标记。界面无法证明安全时先暂停，人工处理后确认所有权及基线再恢复；不要求自动完成所有历史订单对账。submitted 是本地已完成结果，不因柜台状态尚未查询而阻止其他独立请求。

未知异常统一记录阶段、目标、耗时、原生文字和已有文件；只有视觉证据有必要时截图，不预测全部异常或自动点击修复。迟到的拒单弹窗先记录，不凭时间接近归给当前新请求。超时采用单调时钟和有限就绪轮询，同步完成的操作立即推进。

## 公开接口与用户写法

本阶段不新增业务 HTTP 接口；状态、配置和 just 命令按主任务运维扩展升级到实际执行器行为。配置账户后 `just run vnc` 启动自动登录；`just status` 可以区分 logged_in、idle/blocked 和 trading_ready，单纯窗口出现不再满足业务 ready。

用户流程：

```bash
just test
just run vnc
just status
just check
just pause
just screenshot
just resume
```

内部验证使用的业务参数与最终接口相同，例如 `create_limit_order` 的参数为：

```json
{"mode":"sandbox","exchange_id":"CZCE","instrument_id":"RM701","side":"buy","offset":"open","volume":1,"price":2323,"time_in_force":"GFD"}
```

该示例用于领域契约和离线 fixture；在线价格按当次模拟行情选择。正常本地提交返回 `{"request_id":"cfb-123","submission_status":"submitted","order_id":null}`；随后独立查订单/成交，必要时查持仓。下一阶段只绑定 HTTP，不把这些独立查询藏回提交路由。

行为反例：两个请求同时进入时不能各自取得 GUI；调用方断开不能使 submitting 记录重新变为 queued；同键重试不能新增预埋单；市价能力尚未确认不能执行对价限价；只按合约匹配到两条委托必须拒绝猜测目标。

## 测试、验证与阶段过渡

主要入口 `just check` 在工具容器内执行 `uvx ty check`，覆盖共享模型、执行器、IPC、CSV 解析、GUI 适配与原生进程调用方。原生 C helper 通过镜像构建时的严格编译检查，不把类型检查描述为 GUI 或交易验证。

不新增完整执行器测试矩阵、交易压测或在线测试套件；默认 `just test` 继续运行前置少量 pytest 冒烟检查，必要时仅增加最小契约检查。正常和异常行为仍须按任务规范实现，不能用返回假成功简化。

已有独立探针提供固定版本的导入导出、快捷键与原生状态依据；将其转换为唯一受控链路。原生市价、IOC/FOK 等未核验分支保留 unverified 并明确拒绝，不用近似交易替代。开盘切换、夜盘差异、断线恢复和非空表格的后续实测范围准确记录，不要求本轮等待特定市场时段。

本阶段不发布业务 HTTP 路由；前置 unavailable 元数据升级到真实执行器状态。下一阶段复用本阶段模型、队列、错误和持久化，不重新维护一套校验和执行链路。current spec 只同步实际实现，并保留未验证边界。
