# CFB 交易服务与可靠终端执行

## 任务边界

本任务定义并分阶段交付单实例、单账户、SimNow 的交易桥接：FastAPI 提供八个 `/cfb` 业务路由，终端由唯一执行器操作，日志及临时文件按容量治理，just 封装全部容器工作流。配置、请求、响应及进程通信优先采用 Pydantic；按子任务顺序实现。

共同约束继承 [项目原则](../../current_specs/project_principles.md)。完整接口见 [spec_01_api.md](spec_01_api.md)，字段和映射见 [spec_02_models.md](spec_02_models.md)，配置、CLI、日志与生命周期见 [spec_03_operations.md](spec_03_operations.md)。这些扩展共同构成本任务的正式设计。

实施范围：

- 以 FastAPI 替换 `cn_futures_bridge/api.py` 的标准库 HTTP 服务，迁移启动和诊断调用方，保留必要的健康、状态和截图入口。
- 将固定客户端的无弹窗导入导出、键盘发送、必要 GUI 读取及原生状态查询纳入受控源码、镜像构建和测试；独立 debug 探针不得成为正式运行依赖。
- 接入配置账户后的 SimNow 自动登录、账户与交易日核对、登录就绪及执行器健康检测；空账户保留可诊断的登录界面。
- 提供全部业务请求排队、界面准备/复位及轻量防重发；提交完成后快速返回，后续由查询接口确认委托和成交，不把本地提交当作柜台接受或成交。
- 交易状态从已登录快期进程内读取品种原生值，成功时返回 is_trading 二值；不使用日历/时间规则推算、颜色识别或交易所总状态代替品种查询。
- 新建 justfile，迁移宿主 Python/uv 正式入口，所有应用运行、配置校验和测试进入容器；保留 VNC 与 headless 两个变体。
- 去掉 HTTP Bearer 鉴权及 `api.token`，提供明确配置迁移；日志、工件和操作数据库纳入空间治理。

保留固定终端及 Wine 版本、32 位前缀、字体/显示配置、命名数据卷、实例排他锁和现有凭证保护。本文批准接口与入口迁移，不授权升级终端或改写其他历史任务。

范围外：华安实盘验证、多账户调度、另一个项目的鉴权/转发、直接建立 CTP 交易连接、行情 tick/OHLC、策略执行、止盈止损新路由、批量下单或全撤新路由、完整 CTP 原始回报兼容、终端未提供事件的独立临停识别及复杂异常自动修复。

停止线：

1. 八个路由的方法、名称及主要输入可对照参考，CFB 自定义返回和错误语义明确；基础限价 GFD 提交、撤单提交及独立查询形成可运行链路，未实际核验的分支保留 unverified 并在副作用前明确拒绝。
2. 原生市价、IOC/FOK、显式平今/平昨、不同投保标志和两种撤单身份完成能力判定。已有探针支持的能力接入正式链路；尚未核验的分支保留 unverified，不能宣布终端不支持。开盘切换、夜盘品种差异及断线恢复的在线覆盖如实标注，不要求本轮等候市场窗口。
3. 发送前无法唯一确认本地目标、撤单目标不明确、无法恢复临时拦截或复位、超时后可能自动重发，均阻断相应业务交付。回报尚未到达不是本地提交失败，订单号暂缺允许返回 null。
4. 容器入口、双镜像、全路由排队、幂等复位、异常记录及容量清理完成规定验证。大规模长期性能、实盘以及新增业务另行处理，不无限扩展任务。

## 任务规范

### 唯一链路及所有权

HTTP 校验和响应由一个 FastAPI/Uvicorn 服务进程负责；所有终端读写由一个独立执行器进程负责。二者通过有界命令/结果通道通信。原生 Wine 控制器常驻于执行器管理范围，快期实际窗口操作仍在其 GUI 线程执行。

请求经过“校验 → 能力检查 → 入队 → 准备 → 执行 → 必要核对 → 收尾 → 响应”。交易内部优先“无弹窗 CSV 导入 → 回读参数 → 快捷键发送 → 快速读取一次订单 CSV → 收尾”，不循环等待柜台接受或成交。某个环节无法使用 CSV 时按项目原则选择已验证快捷键，再选择原生控件或 GUI。导出失败不自动退回弹窗导出。

交易状态使用专用原生只读路径，调用已加载核心 DLL 的品种查询函数；不改变其他交易和查询的 CSV 优先级，也不扩大为直接调用内部下单函数。原生模块、接口符号、会话及数据有效性均须校验。

八个业务路由的可执行请求每次均进入同一有界 FIFO，包括纯 CSV 和原生状态查询；参数拒绝或幂等结果重放不再次执行。自动登录、取证及重新绑定也由同一所有者协调；健康与已有诊断状态读取不占用业务队列。当前操作完成必要收尾前不能开始下一操作，不能刚入队就返回 submitted。

纯 CSV 仅校验会话、绑定和筛选，结束后处理本次文件，不额外切页。快捷键/GUI 操作先进入明确页面、完整覆盖参数并核对目标；结束时关闭自己打开的已知窗口、释放修饰键、回到约定主窗口基线并验证。准备和收尾须幂等，不重发、不撤销柜台订单、不删除其他人的记录；不把盲按 Esc 当作通用复位。

原生状态读取不改变页面、焦点或键盘状态，不需要界面复位或固定 sleep；读取和会话有效性核对结束后交权。无响应调用仍遵守相同的超时与所有权约束。

保留数据卷排他锁，禁止第二个实例操作同一 Wine/客户端目录。VNC 人工输入前必须暂停执行器；恢复时重新核对身份、弹窗、焦点和未完成操作。不能认为单账户、Python 线程锁或 API worker 数量本身已经解决桌面所有权。

### 状态、校验与失败语义

- 参数类型、枚举、数量、价格和过滤条件在入队前校验；能力不支持在任何导入/按键前拒绝。开始执行时再次确认账户、环境、连接和必要的交易日。
- 使用本次独立文件及当前绑定回读参数；核对合约、方向、开平、价格、数量和唯一目标。部分导入成功也是已有副作用，不能整批盲目重试。
- 返回订单号或关联具体回报时必须有可信身份；取不到时返回 null，不猜测。发送前及撤单前仍须唯一确认本地目标，行号、同价或近似时间不构成身份。
- 排队超时表示尚未执行；提交之后的超时、断线、进程退出或响应丢失可能已经生效，使用 `OPERATION_STATUS_UNKNOWN`。HTTP 客户端离开不取消正在执行的原生操作，也不释放其 GUI 所有权。
- 发送前保留轻量操作记录，防止相同幂等键或重启触发重发；诊断文件清理不能删除该防重发依据。重启后的不完整操作标为 unknown，先由调用方查询及人工核对，不建立自动补单/对账修复系统。
- 窗口/文件就绪以条件判断为准，采用单调时钟、短等待和有限期限。同步完成的原生 CSV 操作不额外加入固定休眠。
- GUI/执行器失联、未知窗口或收尾无法验证时，记录错误并按需截图，暂停后续执行；不能让另一个操作接管仍可能运行的 GUI 调用。submitted 后尚未查到成交是正常状态，不因此冻结队列。

异常处理只建立统一捕获、日志、必要截图、状态返回和安全暂停。已知的明确拒绝可直接返回原因；暂不设计面向未知弹窗的自动关闭、自动重登、补单或复杂恢复。中文 CSV 使用 GB18030，保留现有字体和映射；已有样本未见方块或乱码，不新增字体专项。

具体公共参数、错误与模型以接口扩展为唯一来源；执行和日志配置以运维扩展为唯一来源。

### 分阶段职责

| 阶段 | 交付职责 | 阶段边界 |
| --- | --- | --- |
| 容器入口与运行治理 | just、容器内测试、FastAPI 诊断迁移、无鉴权、配置迁移、日志收集/轮转和工件清理 | 不发布交易占位路由；仍可启动空账户终端 |
| 终端执行与交易闭环 | 单执行器、自动登录、CSV/键盘适配、界面复位、快速提交、独立查询、原生交易状态及防重发 | 通过内部调度契约验证提交与查询组合；HTTP 业务仍未发布 |
| 八路由与集成验证 | 对齐公开接口、序列化、错误映射、OpenAPI、两镜像和整体验证 | 不旁路执行器；补齐跨模块请求、取消、清理及恢复交互 |

主任务规定整体契约，阶段的具体实现与验证由对应子任务承接；不重复运行已被子任务覆盖的同一验证。发现核心能力无法满足时保留准确的限制和阻断，不自行改小验收标准。

## 公开接口与用户写法

`/cfb` 下严格提供三个 POST、五个 GET，后缀与参考接口一致。无 HTTP 鉴权，默认只将容器端口发布到宿主 `127.0.0.1`；公开字段及兼容差异由 [spec_01_api.md](spec_01_api.md) 和 [spec_02_models.md](spec_02_models.md) 冻结。

完整限价请求示例，需已通过能力验证且账户就绪：

```http
POST /cfb/create_limit_order
Content-Type: application/json
Idempotency-Key: rm701-open-001

{"mode":"sandbox","exchange_id":"CZCE","instrument_id":"RM701","side":"buy","offset":"open","volume":1,"price":2323,"time_in_force":"GFD"}
```

正常提交返回 HTTP 202，例如 `{"request_id":"cfb-123","submission_status":"submitted","order_id":null}`，仅表示本地提交完成；由调用方再查 `fetch_orders`、`fetch_trades`，必要时查 `fetch_positions`。不只凭仓位变化判断该笔订单，完整结果访问及错误示例见接口扩展。

`volume=0`、市价请求包含 `price`、混用两种撤单定位字段均在入队前返回 422。`mode=live` 返回 503，不切换账户；返回只包含 CFB 需要的字段，request_id 是 CFB 追踪标识，不兼容 CTP 原生请求号。

用户入口为 `just run vnc` 或 `just run headless`，两者构建并启动同一业务版本；配置继续使用 `config.toml` 与 `config.example.toml`。完整命令和默认值见 [spec_03_operations.md](spec_03_operations.md)。

## 测试、验证与阶段过渡

本轮主要验证入口为 `just check`，在 Podman 工具镜像内执行 `uvx ty check`，必须通过。配置、领域模型与 IPC 优先使用 Pydantic；不以全局忽略类型错误替代修复。

只保留少量必要的离线 pytest 冒烟检查，入口为 `just test`；不新增完整 GUI 自动化测试、交易压测或在线测试套件。检查不挂载真实账户配置、不启动 Wine、不访问柜台。真实构建使用 `just build`，构建与运行入口都由 just 封装 Podman。

代码必须维持前述参数校验、单执行权、幂等和未知结果保护；精简验证不等于删除这些行为。实际未验证的交易分支、状态切换和断线恢复边界在能力信息及当次回复中说明，不能用静态检查冒充交易成功。

依次交付容器运行治理、终端执行器和八路由集成；每阶段在自己的 JJ change 内完善文档和代码，并通过 `just check`。运行治理阶段迁移旧 HTTP/鉴权及宿主入口，执行器阶段接入登录和操作，最后发布业务路由。仅按实际实现同步 current spec/README，未实现的设计不能写成已支持。
