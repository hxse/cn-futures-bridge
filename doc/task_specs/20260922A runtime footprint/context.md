# 运行环境精简

## 使用场景与设计初衷

单账户桥接只需要快期2的二维窗口、原生控件、快捷键及无弹窗 CSV。
通用 Wine 包带入扫描、音视频等依赖，Xvfb 会初始化三维图形库，
scrot 的图像处理依赖也超出保存屏幕 PNG 的需求。
优化优先降低运行内存和构建耗时，镜像体积不是目标；保留中文字体和现有业务能力。

## 方案对比

关闭 Xvfb 的 GLX 扩展可以避免初始化不需要的三维驱动，仍保留二维桌面。
Wine 源码裁剪主要缩小镜像，却引入完整编译成本；预编译包更适合快速构建。
截图使用只读取 X11 屏幕并编码 PNG 的小工具，可以移除截图链路对通用图像库的依赖。
Openbox 同时依赖 Imlib2，其共用库必须保留，因此截图替换本身的镜像收益有限。
进一步更换基础系统、裁剪中文字体或改动 VNC 不属于本次范围。

## 取舍结论

继续使用 Debian slim、32 位 WineHQ 11.0 预编译包、Openbox、完整文泉驿微米黑。
保留 GLX 关闭与轻量截图，不提供 Wine 源码编译链路或相关构建脚本。
只有通过兼容验证的优化进入默认镜像；失败的候选恢复原方案，报告原因。
内存和镜像体积分别测量，不能把未加载库的磁盘体积计作内存收益。
