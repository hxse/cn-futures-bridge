# 自动重连与账户配置

## 使用场景与设计初衷

固定快期2在启动登录时可能提示“连接服务器失败”，服务恢复后仍需手工重启。
网络、服务时段或维护可能导致这种情况，但不能把连接失败当作品种休盘。
用户需要容器长期运行、低频自动恢复，同时让调用方立即知道当前不能执行业务。
原配置只有一组账号，切换模拟与实盘需要反复替换或注释凭证；需要在同一文件
保存两组账号，用总开关选择一个，公共配置只维护一份。

## 方案对比

频繁重启整个容器会中断 HTTP、VNC 和诊断，也没有必要重新构建镜像。
复用旧登录缓存或另开点击线程会破坏账户绑定和 GUI 串行所有权。
在现有调度器中定时回收旧执行器和专属 Wine 会话，再建立新的受控登录，
可以保留 HTTP、桌面与持久化记录，同时确认旧 owner 已退出。
账户按 sandbox/live 分组，启动时解析为唯一当前账户，避免业务调用方分别处理
两组凭证；切换仍通过重启生效，API 请求和重连不承担切换职责。

## 取舍结论

默认失败结束后等待 600 秒再尝试，可配置或关闭；服务端长期不可用时持续低频等待。
仅已识别连接失败或真实连接断开可以自动恢复；凭证错误、未知窗口、
原生调用所有权不明及未决交易不通过自动重登掩盖。
暂停期间停止重连，恢复时重新核验；不切换账户、环境、券商和站点。
不保留待恢复后执行的业务队列，不自动补发任何交易。
配置对外统一使用 sandbox/live；内部 sandbox 仍映射 SimNow，保持已有数据目录
和防重发命名空间。旧配置通过显式命令迁移，冲突报错，完整保留原文件备份。
