# 自动重连与账户配置

## 任务边界

实现固定账户的连接故障识别、600 秒默认重连、状态诊断和离线请求处理。
配置保存公共项及 sandbox/live 两组账户，启动时只选用一组；同步示例、迁移入口、
配置调用方和离线检查，旧单组账户写法退出正常加载入口。
保留八个业务路由、参数、幂等记录、容量治理、单账户约束和已识别文档确认。
替换连接故障永久阻塞的旧策略；不增加日历判盘、运行中环境切换或交易重放。
不引入宿主常驻任务、容器定时重建、额外 GUI owner 或新的在线测试入口。
正常休盘且连接有效时不重登；非连接故障保持人工处理，不自动修复任意终端异常。
交付以离线契约检查、类型检查和两种镜像构建通过为准；真实服务恢复及跨交易日
运行需后续在线观察，不把外部服务器当前可用作为离线实现的通过条件。

## 任务规范

### 账户分组、校验与迁移

bridge.mode 是唯一选择开关，默认 sandbox，只接受 sandbox/live；accounts.sandbox
和 accounts.live 使用同一个 Pydantic 账户模型。Settings.account 为只读派生访问器，
不是可输入字段；BridgeConfig.environment 从 mode 映射为 simnow/live，仅供内部使用。
模拟环境的空 broker_id/site 沿用 9999/电信2，实盘必须明确选择 6020 和一套/二套。
所有分组都严格校验字段名、类型与字段基本格式；仅选中组检查凭证配对和环境、
券商、站点组合。选中组账号密码均空时只启动登录界面，仅填一项则加载失败；
备用组可以为空或待补全，选择时才进行业务完整性检查。

公共配置只有一份。容器身份摘要只包含公共配置与当前账户身份，不包含备用组
或密码；编辑备用账号不改变当前容器的身份摘要。账号密码不写入日志，日志过滤
覆盖两组凭证。当前账户、配置和 mode 在启动时固定，切换或修改当前凭证须重启。
请求 mode 与启动选择不一致继续返回 409，不借请求或重连选择另一组账号。
session 目录摘要、原生 profile 和 SQLite namespace 保持原有 simnow/live 身份定义。

正常加载拒绝旧 [account]、bridge.environment 和 api.token，并提示 just migrate-config。
迁移按旧 environment（省略按旧默认 simnow）归档旧 [account]；simnow 映射 sandbox，
另一组填入示例中的空凭证配置，保留公共自定义值，同时移除旧 api.token。
旧账户/环境结构与新 accounts/mode 结构混用时明确拒绝，不猜归属或覆盖新配置。
转换后先按新模型验证；非法配置不写入。首次备份使用 config.toml.bak，已有备份时
使用 config.toml.<唯一编号>.bak，均为 0600、不覆盖；备份与临时文件忽略跟踪及构建。
原文件按字节备份后原子替换为新 TOML，目标文件为 0600；改写前发现文件变化则停止。
新格式再次迁移只验证、不改写、不再生成备份。注释保存在原文件备份中，备用凭证
由用户填写，不从旧注释推断账户。

### 识别与就绪

登录等待从原生窗口树读取目标登录窗口内可见非输入控件，精确识别
“连接服务器失败”，记为 CONNECTION_FAILED；不读取像素，不记录整个窗口树或凭证。
密码错误、账户锁定、验证码等已识别提示记为 LOGIN_REQUIRES_ATTENTION。
未知阻塞窗口记为 GUI_RESET_FAILED 并保存一次必要截图；普通连接失败不截图。
“保证金监控中心”为已核实的附属网页窗口：同一终端进程与 GUI 线程、顶层
#32770、精确标题、owner 为当前配置的主窗口、可见直接子控件 1224 为
AtlAxWinLic100，且没有 IDOK/IDCANCEL 确认按钮。全部匹配后向该窗口投递
WM_CLOSE，关闭动作不依赖网页正文是否为空或加载成功，不按通用 Enter/Esc。
复用显式已知窗口扫描、登录等待、基线及 resume，覆盖启动后迟到的弹窗；
普通窗口读取和显示/激活回调不能关闭它，暂停期间不扫描。与其他文档处理
共享每终端会话最多 8 次预算，同一窗口去重，等待关闭后再次确认基线。
关闭完成按窗口不可见确认，允许快期缓存句柄；观察到隐藏后结束本轮去重，
同一窗口再次显示时重新核对并关闭，仍受会话总预算限制。
标题、归属或控件不匹配仍按未知窗口处理。

成交结果通知允许标题“成交通知”及严格的“(i/n) 成交通知”，其中 i/n 为正整数、
i 不大于 n。须核对同一终端进程和 GUI 线程、顶层 #32770、配置主窗口 owner、
直接子控件：1 为“确定”按钮，1299 为“不再提示成交通知”的 owner-draw Button，
7501 为含合约、买卖、开平、成交量、成交价字段标记的 Static；同时核对上一条/下一条
1245/1246 按钮并拒绝 IDCANCEL。空正文可以有界等待，非空正文不匹配不操作。
处理严格分阶段：未勾选时仅投递一次 BM_CLICK；后续扫描回读 BM_GETCHECK 为
BST_CHECKED 后才投递确定按钮通知。已勾选则不重复点击；点击无效不重试切换状态、
不提前确认，超时保留现场。记录勾选请求、勾选核对、确定请求和窗口关闭，不记录
成交明细，不把成交通知当作 API 报单或成交成功的判据。
该通知与现有窗口共享最多 8 个处理轮次预算，每轮两步只占一份；复用 managed_windows
和 GUI 队列，普通读取、回调和暂停时不点击。观察到隐藏或销毁后清除本轮标记，
同一句柄再次弹出重新匹配。正文或控件不符的交易确认框仍保持未知窗口处理。
登录超时没有明确连接证据时保持人工核对，不把所有超时视作网络故障。
初次主窗出现后仍等待账户和连接数据；有真实连接未就绪证据时可归为连接失败。
已登录会话的交易或行情连接断开记为 CONNECTION_LOST；身份不符、原生对象
失效、人工重登代次变化和未知 GUI 状态不自动接管。品种休盘不影响连接就绪。

### 串行恢复

恢复由现有调度线程持有唯一执行权：停止旧 worker/控制器，确认其退出，
停止专属 Wine 会话并等待退出，然后引导 Wine、启动固定终端和新 worker。
新 worker 使用新 IPC 代次，从登录窗口执行完整配置核对及登录流程；
清除旧内存绑定，不接管旧账户缓存。HTTP、Xvfb、VNC 和持久化文件保持运行。
任何旧 owner 或 Wine 退出无法确认时停止恢复，不启动第二个 owner。

首次失败或运行中断线结束后以单调时钟计时，每次失败再等 interval_seconds。
只保存一个定时任务；没有账号、关闭功能、人工暂停或正在停止时不发起恢复。
凭证错误、未知弹窗、存储失败、原生调用未退出及未知交易结果阻止自动恢复。
每次登录继续使用 startup_timeout_seconds，明确失败提前退出；不扩大业务步骤超时。
恢复成功须重新核验真实账户、交易/行情连接、会话与 GUI 基线，并处理已支持
的隐私/协议/结算确认；有可信交易日才发布 trading_ready。

pause 停止新尝试并等待正在执行的 owner；等待超时不宣称可以人工接管。
resume 对待重连的已知故障解除暂停并恢复原计时，期限已过则尽快尝试；
其他情况沿既有核对链路处理，不清空未决交易、不补单。

### 请求、日志与失败

环境、参数及能力校验保持原顺序；有效新业务请求在离线或重连中立即拒绝。
发现离线时清退尚未开始的队列项，标明未执行；不等恢复后重新派发。
已开始操作保留 submitted/rejected/unknown 事实，先收尾和持久化，再判断能否恢复。
已有幂等响应仍可读取；请求频率不改变恢复期限，也不触发额外登录。
交易状态查询断线时报错，不返回 false；查询失败不返回旧值或空仓位。

记录故障类型、失败时间、重连次数、尝试开始/结束与耗时、下一次时间和恢复成功。
正常等待不刷日志；日志和必要截图分别使用现有 200 MiB/300 MiB 容量预算。
截图只在未知 GUI、卡住等确有必要时产生，普通断线不重复截图。

## 公开接口与用户写法

唯一配置文件为 config.toml，核心用户写法如下；其他公共分区维持既有默认值：

```toml
[bridge]
mode = "sandbox"
data_dir = "/data"
startup_timeout_seconds = 90

[accounts.sandbox]
broker_id = "9999"
site = "电信2"
username = ""
password = ""

[accounts.live]
broker_id = "6020"
site = "一套"
username = ""
password = ""
```

填好两组后，只改 bridge.mode，再执行 just restart 或 just restart vnc。
bridge.mode="simnow"、选中组仅填写账号、live 站点不匹配均报配置错误。
旧配置先执行 just migrate-config，再重建重启；迁移不会登录或停止当前终端。
reconnect 配置节可省略，默认间隔 600 秒；严格拒绝非整数间隔及越界值：

```toml
[reconnect]
enabled = true
interval_seconds = 600 # 60～86400；改为 900 即每 15 分钟。
```

未就绪的新业务请求返回 503/SERVICE_NOT_READY，尚未执行的 submission_status 为 null。
执行中才发现断线可返回 503/CONNECTION_LOST，并保留既有副作用事实。
存在有效重连计划时 503 附 Retry-After，值为距离下次尝试的秒数，至少 1；
重连进行中可用配置间隔作为建议，不能保证该时间后已恢复。暂停、人工处理、
关闭重连时不提供此头。

```bash
curl -i 'http://127.0.0.1:45173/cfb/fetch_balance?mode=sandbox'
curl 'http://127.0.0.1:45173/v1/status'
```

```json
{"request_id":"cfb-example","submission_status":null,"order_id":null,
 "error":{"code":"SERVICE_NOT_READY","message":"执行器未就绪或已经暂停","details":null}}
```

/healthz 仍为 HTTP 存活 200；/v1/status 始终可读；/readyz 未就绪为 503。
ServiceStatus 增加 reconnect 对象：enabled、interval_seconds、state、attempts、
last_failure_at、last_error、next_retry_at、manual_required。时间为 UTC ISO8601 或 null；
state 为 idle/waiting/reconnecting/paused/manual/disabled；attempts 统计本实例自动恢复尝试，
不含首次启动，成功不抹除历史故障。状态读取没有 GUI 副作用。

## 测试、验证与阶段过渡

在本 change 中直接替换旧连接失败策略，无需双轨兼容或新队列。
分组账户采用同一加载入口，旧格式只能通过显式迁移转换；不保留双签名或字段别名。
just test 离线验证示例加载、两模式选择、备用组未配置、选中组配对校验、
备用变化不影响签名、旧目录与幂等 namespace 不变，以及迁移保留凭证和公共配置、
冲突/非法配置不改写、备份不覆盖且权限正确、重复迁移无副作用和旧输入明确退出。
just check 通过；just test 使用离线 fixture、假时钟和模拟进程，验证识别正反例、
600 秒默认值与非法配置、失败后计时、暂停/恢复、恢复成功与再次失败、
凭证/未知状态不盲重试、未就绪 503/Retry-After、队列清退和幂等结果保留。
验证恢复顺序为旧 worker 退出、Wine 退出、启动新会话；退出失败不得创建新 owner。
不真实等待十分钟，不发送实际交易，不读取用户账号配置。

owner、进程/线程、控件、确认按钮、普通读取、过期和次数预算的拒绝行为。
可在无网络隔离 Wine 中用原生窗口 fixture 验证实际 WM_CLOSE；线上仅检查
用户指明的附属窗口关闭和只读就绪状态，不操作交易确认或报撤单。
成交通知验证动态序号标题、已勾选和未勾选、点击后回读及确认顺序、重复扫描、
点击无效、错误标题/控件/正文/归属、暂停/普通读取、次数预算和隐藏复用。
当前实际通知仅确认设置勾选和关闭，不通过下单制造通知；不新增在线交易测试。
不新增默认在线测试；本任务不以实盘下单或撤单验证恢复。
