# 结算单自动确认

## 任务边界

在固定快期2的受控登录阶段及执行器界面检查中自动确认已识别的结算单。
沿用既有隐私、协议及向导的启动期限制，处理启动完成后才到达的结算单。
保留账户绑定、环境匹配、单执行器队列、交易确认归属及未知窗口失败规则。
不新增路由或配置，不做交易测试、不读取内部交易函数、不扩大为任意弹窗确认。
交付以自动完成 SimNow 结算确认、恢复只读查询且不误点其他窗口为停止线。

## 任务规范

确认前同时核对以下事实：

- 窗口属于已绑定终端进程及 GUI 线程，处于启动期或执行器持有执行权的结算扫描内。
- 顶层可见窗口的类为 `#32770`，标题严格为“确认结算单”。
- owner 是当前环境、券商、站点对应的主窗口，且属于同一进程和线程。
- 直接子控件 `1/2` 为 Button，标题严格为“确认/取消”，确认前两者可用。
- 直接子控件 `7601` 为可见只读 RichEdit20A。
- 完整读取正文，长度为 128～524288 个 UTF-16 单元且未发生截断，包含“结算单”“客户号”“资金状况”及 `Client ID`。

仅向核对后的对话框投递 IDOK/BN_CLICKED，不发送通用 Enter、不点击坐标。
正文在终端 GUI 线程内通过 RichEdit 的 Unicode 接口读取，避开 ANSI 消息转换截断。
同一窗口不重复发送，每个终端会话内文档自动确认合计最多 8 次。
正文、按钮未就绪时只等待，不把待处理结算窗口当作未知弹窗立即终止。
窗口读取会补充检查已显示的文档，解决显示事件早于正文加载的问题。
完成启动的原生命令再次检查已识别文档是否仍待处理；未关闭时保持启动阶段。
启动期间等待受原有启动期限约束；运行期间使用 step_timeout_ms，超时明确失败。
启动后只在已有的空闲探测、请求前后界面检查及显式恢复流程中扫描结算单；
调用前沿用账户/会话核对，由唯一执行器串行持有 GUI 执行权，不重登、不无限重试。
结算单始终只由执行器显式扫描或启动完成检查确认，异步显示/激活回调不确认结算单；
普通窗口读取也不点击结算单。隐私、协议及向导的原有启动回调保持原规则。
人工 pause 成功后，现有调度器停止探测和请求，不能在人工接管期间确认结算单。

确认次数通过内部 Pydantic 回报进入结构化日志；日志只记录窗口类别和次数，
不保存正文、客户号、结算金额。记录投递请求和窗口关闭；业务步骤超时不放宽。
更新原生共享区版本，控制器与 DLL 一起构建，防止混用布局。

## 公开接口与用户写法

没有公开接口或配置变化。已配置 SimNow 的用户继续使用：

```bash
just restart vnc
curl --fail http://127.0.0.1:45173/readyz
curl --fail 'http://127.0.0.1:45173/cfb/fetch_balance?mode=sandbox'
```

已识别的结算窗口自动处理；“确认下单”等其他标题不会被此流程确认。
窗口控件不匹配或正文未能在启动期限内就绪时，readyz 仍为 503，保留错误和现场。

## 测试、验证与阶段过渡

执行 `just check`、`just test`、`just build`，原生 helper 使用既有严格编译规则。
少量离线 pytest 覆盖启动等待和未知窗口拒绝，不连接账户。
显式运行临时离线原生窗口夹具，验证真实 WM_COMMAND 接收：匹配、正文延迟、
按钮延迟、重复调用、错误标题/控件/正文/owner/进程/线程、关闭阶段和次数预算；
同时核对启动后只有显式结算扫描能够确认，普通回调与读取保持被动。
夹具位于 debug，隔离网络和账户，验证后删除，不加入运行镜像或默认在线流程。

用户授权当前 SimNow 在线验证：保留待确认状态，沿正式重启入口观察自动确认日志、
窗口消失、真实身份及连接就绪，以及余额、持仓等只读查询。
确认成功以窗口退出和服务就绪为依据，不把投递消息成功当作柜台确认已完成。
不测试实盘确认或任何交易动作；不同报告模板必须重新核对，不能放宽识别条件。
