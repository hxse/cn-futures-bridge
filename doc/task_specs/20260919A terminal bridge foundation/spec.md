# 中国期货终端桥接的项目初衷与第一版蓝图

## 任务边界

### 本任务交付

本任务是 `cn-futures-bridge` 的首个正式任务，保留项目蓝图并交付最小 SimNow 启动骨架。meta、context、spec 分别负责定位、动机与取舍、约定与验证门槛，须在脱离聊天记录后仍能指导后续实施。

本阶段落地基础代码、TOML 配置、固定官方快期2包、两个镜像、启动管理和诊断接口，验证空账号启动。具体公开写法、失败语义与验证入口见 [spec_01_bootstrap.md](spec_01_bootstrap.md)。不填写账号、不登录或报撤单；不得改动 AGENTS.md、其他项目或远端历史。

已实施的启动行为同步 current spec 与 README 使用说明；未实施的交易蓝图仍留在本任务。不建立任务索引、执行报告或生命周期状态文件。

### 第一版目标范围

- 单个容器中的一个专用交易会话；调试阶段先用 SimNow，最终适配华安普通快期2客户端。
- Debian slim 或 Ubuntu 精简环境、Wine、必要运行库与中文字体、固定虚拟屏幕、自动化控制器和 REST 服务，交付仅远程桌面组件不同的 headless 与 VNC 两个镜像。
- 资金与保证金、持仓、挂单、委托与成交查询。
- 开仓、平仓、限价挂单、撤单，每笔请求明确手数。
- 利用客户端现有能力设置、查询、修改和取消止盈止损条件。
- 登录、版本、连接、导出、界面和交易错误的明确反馈，以及不确定结果的处理。
- 验证快期本地日志作为增量事件来源的条件，每个操作阶段设置检查点，结合业务状态捕获异常，GUI 继续兜底。
- 对快捷键填单与文件导入路径作等价业务的耗时和可靠性比较，单独识别导入、导出弹窗的影响，按实测选择主要路径。

查询与交易能力的业务边界在本任务中确定，完整业务 HTTP 契约尚未冻结。启动阶段的配置、CLI 和诊断 API 由启动扩展规范冻结，不允许把未实现的业务描述当作已经发布的 API。

### 范围外事项

- 自研 CTP 登录、终端信息采集、交易协议或直接连接柜台的第二条执行链路。
- 依赖付费专业版 API，或要求快期必须提供交易 API。
- 第一版同时适配文华、MT5、多个快期版本或多个期货公司。
- 多账户联合交易、复制交易、自动策略决策、套利执行、行情研究或回测平台。
- 以 OCR、视觉模型或屏幕像素承担全部业务操作。
- 高频性能保证、永久锁定旧客户端的可用性保证、未经实测的内存或延迟承诺。
- 银期转账、开户、修改资金密码等账户管理动作。

Windows 桌面系统是已接受的备选方向，不与 Linux + Wine 一起作为第一版的双平台交付要求。若 Linux 兼容性门槛不通过，后续实施任务须明确调整范围后再落地 Windows 方案。

### 停止线

启动阶段的停止线是：完整保留蓝图，基础文件落地，两个镜像中的快期2可显示登录窗口，空账号可启动，状态与截图诊断可用；之后等待用户填写账号，不提前实现或测试登录交易。

后续第一版运行能力的停止线是：针对一个确定的华安客户端版本，按等价流程实测选定各业务路径，形成唯一执行链路，业务功能和异常语义有验证依据，并提供可复现的部署与资源记录。尚未通过的登录、状态读取或交易结果确认不得降格为已支持能力。

## 任务规范

### 唯一正式链路与所有权

正式链路为：外部 REST 请求 → 请求校验与串行会话控制 → 按业务选定的快捷键填单或文件导入路径操作快期2 → 经验证的结果读取 → 结果核对 → 对外返回。

| 组件 | 唯一职责 |
| --- | --- |
| REST 边界 | 接受明确的业务意图、校验参数、返回结构化结果与错误，不直接操作桌面 |
| 会话控制器 | 拥有账户和桌面会话，串行调度查询、导出、交易及人工接管状态 |
| 快期2适配器 | 解释指定版本的快捷键、板块、文件导入导出格式、已选业务路径和必要界面补充读取 |
| 日志观察器 | 增量读取已验证的快期日志，提供带来源的事件及读取健康状态，不操作桌面或发送交易 |
| 结果记录 | 关联外部请求、阶段证据与可确认的委托、成交或条件单，保存恢复所需的请求事实 |
| 快期2客户端 | 完成自身采集、登录认证、柜台连接、发送指令和显示回报 |
| VNC | 查看、调试和显式人工接管同一桌面，不作为交易数据传输协议 |

一笔交易只能通过快期2这一条执行链路发送。不得在界面操作失败时偷偷改用 CTP、另一账户、另一终端或其他 SDK 补发。

一个账户的界面动作由一个控制器拥有；并发 HTTP 请求不等于并发按键。导入、查询导出及其对话框同样占用会话，必须与交易排队协调。不得让两个进程同时写同一个 Wine 配置目录或竞争同一桌面焦点。

### 操作优先级与界面状态

1. 快捷键填单与文件导入均为主要候选，先按“路径比较与选择验证”完成实测，再为对应业务选择其中一条；不预设文件路径更快。
2. 键盘负责已验证的定位、输入、菜单、文件选择、发送和启停动作；可导出的数据通过导出解析读取，并单独验证时效和耗时。
3. 对已验证可观察的阶段，优先增量读取快期日志并核对业务状态；其余字段或交互才使用界面文本、控件或局部截图识别。文件路径变慢本身不是改用 OCR 主链的理由，日志不能替代必要的操作前页面和参数核对。

每种业务及已明确支持的工作量场景只有一个选定主路径，统一使用同一请求记录和结果核对规则。比较阶段可以实现最小候选流程，不形成两套长期独立的交易服务；允许单笔用快捷键、小批量用文件，但必须由测量结果和明确规则支持，不因此新增批量 REST 契约。

快捷键与文件路径不是对同一动作的盲目重试链。生产中不并行竞速、不双发，也不因本次文件导入变慢就自动改为键盘再下单。进入兜底必须知道前一动作是否产生副作用，不能在提交结果未知时换另一种方法重新提交。

操作前确认账户、当前窗口、板块和焦点；输入后核对关键字段；提交后核对业务结果。不同页面相同快捷键可能有不同含义，适配器必须包含这个上下文，不能只保存一个全局按键映射。

布局、列顺序、排序、筛选和快捷键配置属于适配环境。凭导出时的行号直接撤销当前界面第 N 行不可作为可靠定位；操作前必须确认对应委托身份，无法确认时停止。

键盘填单须明确设置合约、买卖方向、开平、手数和价格，处理上次输入残留及自动补价。不能依赖自动开平推断用户意图，不能让默认手数替代本次指定手数。

每一步等待均有明确期限；可重试动作和次数由已验证流程限定。未知弹窗不自动按回车确认；无法确定界面状态时停止操作并报告。

GUI 识别仅处理必要局部。不能识别的金额、价格、手数或订单编号不得猜测、四舍五入补全或当作零值继续交易。

### 文件导入与导出的业务边界

导出用于取得业务数据或客户端原生模板；新增交易的文件路径是：按真实模板生成指令文件 → 触发导入 → 核对结果及参数 → 选中新导入指令 → 按意图立即发出或启动条件单 → 查询实际结果。不能把导出本身或导入成功当成已经向柜台发出委托。

选定版本必须确认手工预埋单和条件单的模板差异、价格、手数、方向、开平与今昨仓字段，以及执行位置。不能把等待进入交易状态的预埋单误当作立即下单，也不能把普通价格条件单直接等同于完整的止盈止损联动。

文件选择、导入结果、保存与覆盖确认均是显式流程步骤。验证每次是否出现、需要几次确认、能否直接用键盘输入完整路径，以及窗口的打开和关闭时机；不假设存在无对话框导入、目录监控、记忆路径或可安全复用的常驻窗口。

可以验证直接输入完整路径等减少目录浏览的方式，但优化必须包含参数和结果核对，不通过跳过确认业务结果来获得更短测量值。固定目录或文件名若被采用，也必须能区分本次内容与上次残留。

导入须核对预期记录数、实际成功数量和导入后的关键参数。部分成功、重复导入、无法区分本批与历史记录时，停止发送并报告；不能直接全选列表发出，也不能把有副作用的导入失败当作可无条件重试。

修改或删除文件中的一行，不代表修改或撤销已经报入柜台的委托。未证实普通快期2有文件撤改单能力前，这些业务仍使用已验证的客户端操作；专业版的篮子下单能力不视为普通快期2已具备。

### 客户端、运行环境与受控升级

调试先固定含原生 SimNow 站点的官方快期2包；华安适配阶段另选当前兼容的完整包。记录安装包校验值、安装后实际程序和关键依赖版本、Wine 版本、必要运行库、字体、显示配置、快捷键配置、导入导出格式、日志格式及已选业务路径的对应关系。

运行时必须检查实际客户端版本，而非只读取镜像标签。持久化目录中的自更新可能改变程序；仅固定镜像或安装包不能证明运行二进制仍相同。

自动升级的触发时机、能否配置关闭及文件改写行为，必须在对应包上验证。未验证前不能假定有关闭开关；不能以阻止更新请求推导出旧版仍被柜台接受。

版本变化、升级提示阻断业务或柜台不再接受旧版时，服务必须明确报告需要升级，并停止未经验证的自动发单。不得自动下载新版本后立即继续原流程。

新版本进入独立验证环境，复核快捷键、导入导出字段及弹窗、日志格式与事件含义、登录、报撤单、条件单和异常行为后才发布。影响已选流程时重新比较其完整耗时，不能照搬旧版本的速度结论。客户端改变不应直接改变对外业务含义；若确需改变公开契约，先明确更新相应规范。

保留旧镜像用于排查和允许范围内的回退；柜台已停用旧版时，不承诺回退能够恢复交易。

### Linux、字体与两个镜像

Linux + Wine 为优先路线。基础系统、Wine 和客户端的具体版本依据兼容性验证选择，不在没有安装包证据时任意锁定一个版本号。客户端的位数及相应 Wine/WoW64、运行库需求必须实查。

使用 Xvfb 或经验证的同等虚拟显示方式，固定分辨率、DPI、缩放、字体、字号、语言环境和时间区。必要时使用最小窗口管理组件维护焦点，不以完整桌面套件作为默认依赖。

中文字体作为镜像的显式依赖，按实际显示验证选择文泉驿微米黑或 Noto CJK 等字体，并固定 Wine 中必要的替代配置。要覆盖菜单、资金数字、合约、导出对话框和错误弹窗；显示正确与文件编码正确分别验证。

第一版使用一份 Containerfile 和公共构建层产生两个变体，不维护两套业务代码或彼此独立的运行环境：

| 变体 | 构成与用途 |
| --- | --- |
| headless | 包含 Wine、快期2、字体、虚拟屏幕、自动化、日志观察、截图能力和 REST 服务；不包含 VNC 远程桌面组件 |
| vnc | 复用 headless 的公共环境，仅增加 VNC/noVNC、必要代理及其服务启动和访问入口，用于实时查看与人工操作 |

同一发布版本的快期2、Wine、运行库、字体、分辨率、DPI、布局、配置、日志规则、自动化流程和业务 API 必须一致。加入远程桌面依赖不能隐式升级公共组件或改变字体回退；不得按是否带 VNC 分支实现不同的交易或异常处理逻辑。

两个变体都使用同一个公共虚拟显示方案。headless 表示没有远程桌面入口，不表示不运行 GUI；仍可按需截图、记录日志或启用经验证的录屏。VNC 必须连接自动化所用的同一显示；容器不因 noVNC 增加完整浏览器。

远程调试入口与业务 API 的访问控制分开配置，凭证不进入镜像；人工接管前暂停自动操作，结束接管后重新确认状态再恢复。没有 VNC 时，异常证据的采集与返回不能失效。

同一账户的两个变体二选一运行。切换时停止旧实例，再用另一变体接入同版本兼容的持久化数据；重新确认客户端版本、登录、委托、条件单和未完成请求，不重放交易。此方式不承诺无中断热切换，也不允许两实例共写同一 Wine 目录。

### 资金、持仓和订单数据

资金返回中区分余额、权益、可用资金、已占用保证金及冻结保证金；不把保证金占用等同于交易所或期货公司的保证金率。本任务必须覆盖保证金金额，费率查询不作为已承诺能力。

优先获取资金详情中的柜台数据。使用客户端本地计算值时明确标识来源，不把本地计算字段冒充柜台回报。

持仓必须保留交易所、合约、多空方向、今仓与昨仓以及可确认的可平和冻结数量，不用一个净持仓数字丢掉开平信息。

订单和成交按可验证的唯一身份关联。区分活动委托、拒绝、部分成交、全部成交、撤单及无法确认的状态；委托数量、成交数量和剩余数量含义明确。实际可导出的标识组合要在接口设计前确认。

导出使用一次操作对应的可识别产物，并检查生成时间、写入完成、格式、字段和记录范围。不能读取上次导出文件冒充本次查询，也不能把只导出的选中行冒充全部记录。

按实际版本确认文件类型、编码、数字格式、表头和空值表示，不默认所有文件都是 UTF-8 CSV。缺字段、解析失败、未登录和导出超时分别作为失败，不能返回空持仓或零余额掩盖错误。

对外数据附带账户、数据来源、采集时间和可判断的连接/新鲜度信息。跨资金、持仓、委托的多次导出不是同一时刻的原子快照；接口不得声称具备这种一致性。

### 交易、手数和条件单

交易在接受请求和即将操作客户端时分别校验。前者检查必要参数、格式和取值，后者检查实际账户、会话状态、数据可用性及委托前置条件；失败时不得发送部分指令。

合约、交易所、买卖方向、开平标志、数量和价格必须明确。手数为符合目标合约限制的正整数；价格不得静默改为默认价或对手价。平今、平昨与普通平仓根据合约和实际持仓明确处理，不用反向开仓代替平仓。

限价开平仓与限价挂单是第一版的明确目标。额外价格类型仅在客户端、柜台和接口契约均确认后暴露；未知或不支持的类型应拒绝，不能擅自映射成另一种委托。

撤单必须针对已确认的委托身份。撤单期间可能成交，最终结果以读取到的业务状态为准；发送撤单快捷键不等于撤单完成。

止盈止损使用客户端原生条件单能力。明确合约、保护方向、适用数量、触发条件、触发价、触发后报单方式与价格，以及本地或服务器执行位置。条件单建立、启动和触发后的真实委托是不同阶段。

服务器条件单只在华安对应柜台验证支持后使用。不支持时须明确报告或由调用方显式选择本地方式，不能静默降级成本地条件单。

本地条件单依赖客户端与网络运行。重启后须重新读取实际启停状态；不能因为配置仍存在就宣称保护仍在生效，也不能在未核对条件和持仓时自动补建重复保护单。

开仓附带止盈止损、为已有持仓设置保护、调整数量或价格、取消条件单，分别验证。部分成交、手工平仓及另一保护条件触发后的剩余条件，要准确查询和表达；未验证原子互斥关系前不得宣称 OCO 保证。

### 副作用、异常与结果未知

对外区分请求被本地接受、客户端动作已执行、柜台接受/拒绝和实际成交。查询与 HTTP 通信成功都不能代替交易业务成功。

每个有副作用的请求需要可持久关联的请求标识。同一标识的重复提交不得产生第二笔指令；相同标识但不同参数必须拒绝。具体标识字段和保存规则在接口设计阶段冻结。

提交后超时、连接中断或进程重启时，若无法证明是否已经报单，结果为未知。先核对委托和成交；不能自动重放，也不能谎报“失败，未下单”。无法唯一关联时保留未知结果并暂停有歧义的后续操作。

断线前排队但已过期的意图不得在重连后继续执行。请求的有效期表达和各动作的超时数值须在对应接口与适配设计中确定，不允许无限等待或无限重试。

异常至少覆盖：未登录、认证/采集失败、连接中断、结算确认或其他待处理提示、版本不匹配、窗口/焦点异常、导出失败或陈旧数据、参数错误、资金/持仓等业务拒绝、未知提交结果。

优先依据已验证的快期日志与业务记录获取原因，必要时补充反馈文字、弹窗文本、截图与识别结果。按下节规则确认日志适用范围，保留原始错误信息、来源和发生阶段，不能只返回模糊的“操作失败”。

异常证据避免泄露凭证；截图及账户记录按敏感数据处理。未知弹窗或关键数据缺失时停止自动操作，允许通过 VNC 查看和接管。

### 日志观察与阶段检查点

在选定的华安客户端版本中确认日志实际目录及与 Wine 路径的对应关系，不照搬其他版本或快期3的目录。只有格式可解析、事件含义和覆盖范围明确、关联字段足够、写入延迟满足该阶段要求的日志，才可参与自动判定；存在日志目录本身不等于满足这些条件。

| 证据来源 | 用途与边界 |
| --- | --- |
| 桥接服务操作日志 | 记录请求身份、阶段、计划动作、实际发出的按键/文件动作、耗时及观察结果；不能单独证明客户端或柜台接受 |
| 快期自身日志 | 提供客户端已记录的事件、错误和原始信息；仅在已验证覆盖范围内参与判断，不假设包含所有动作 |
| 委托、成交、持仓和条件单记录 | 核对业务身份、状态和数量；按前述读取及新鲜度规则使用，不能用自写日志替代 |

符合条件时，后台只读跟踪新增日志，将解析事件交给同一会话控制器与结果核对流程。普通执行不在每个阶段全量读取、通过菜单导出或打包整份日志，也不为划分阶段清空或改写客户端日志。诊断确需额外导出时作为有界操作单独安排并计入耗时。

每个阶段在动作前记录请求身份、当前日志读取位置和预期结果，动作后在期限内等待相应的新事件或业务状态；应能捕获迅速返回及延迟到达的事件。没有对应日志的阶段使用经验证的状态或界面检查，不能无限等待一个客户端不会写出的事件。

事件优先按账户、交易会话/交易日及实际可得的委托或条件单身份关联，再核对合约、方向、数量等上下文；仅凭时间接近、相同合约或出现“成功”文字不足以归属当前请求。桥接请求 ID 不被假定存在于快期日志中。历史记录、其他订单及异步回报不得误推进本次阶段。

“按键已发送”“文件已写入”只证明桥接动作完成，“没有错误日志”不证明操作成功。客户端报单事件与柜台接受、成交仍须区分。日志和业务状态冲突、关联有歧义或阶段结果不明确时保留证据并报告未知，不自动补发。

逐阶段验证日志是否覆盖登录/断线、导入结果、拒单、撤单失败及条件单相关事件。文件窗口未取得焦点、输入未生效、未知弹窗等可能没有日志；日志观察不能取消操作前的页面与参数核对，也不能完全替代 GUI 兜底。

增量读取须处理编码、未写完的记录、缓冲延迟、文件轮转/截断/替换以及重启和跨交易日；恢复读取不把历史事件当作新操作结果，不因重复消费产生副作用。读取位置和必要关联状态按恢复需求保存，原始内容和解析结果分开保留。

读取失败、格式变化、日志陈旧或观察器积压必须显式报告，不能当作“客户端没有异常”。仅影响辅助证据且已有独立可靠结果来源时可继续按既定流程核对；若该阶段依赖的证据因此缺失，按前述超时和未知语义停止推进。不得擅自延长交易期限等待日志刷新。

日志观察器不占用 GUI 焦点、不发送交易、不阻塞界面等待自身全量导出，读取频率与缓存有界。必要截图和原始日志片段按异常需要采集，两个镜像使用相同规则并对凭证等敏感内容作一致处理。

### 持久化与运行资源

明确区分程序安装内容、客户端/Wine 状态、快捷键配置、导出文件、两类日志及请求结果记录。需要跨重启保留的日志读取位置和请求关联等内容使用持久化存储，两个镜像沿用同一数据约定，但不得因此绕过运行版本校验。

健康状态区分进程存活、客户端可操作、账户已登录、数据可读、日志观察可用和业务能力就绪。服务进程还活着不等于可以安全执行交易，日志读取失败也不直接等同于柜台断线。

资源评估分别报告两个镜像的大小、首次安装后的持久卷占用、运行内存峰值和 CPU。至少覆盖未登录、登录空闲、行情更新、连续查询、报撤单、异常恢复、日志持续读取，以及 headless、VNC 服务运行但无人连接、VNC 已连接三种场景。

本任务没有确定资源硬上限；后续基于实际包测量再决定优化目标。避免安装无关行情分析组件、完整桌面和重型识别模型；不能为宣称轻量而删除正常登录或异常处理所需依赖。

## 公开接口与用户写法

### 当前公开面与后续冻结点

本阶段只新增启动扩展规范定义的 TOML 配置、CLI 和诊断 API。以下是完整第一版必须保留的业务契约，不是已经发布的交易 HTTP 路径或 JSON 模型。

镜像变体命名约定为 `cn-futures-bridge:<版本>-headless` 与 `cn-futures-bridge:<版本>-vnc`，同一版本成对交付并共享业务契约。启动阶段使用本地 0.1.0 标签，不向远程仓库发布镜像。

后续接口设计阶段必须一次性冻结：路由和方法、鉴权方式、账户范围、请求/响应字段、金额与价格表示、时间与交易日、订单和条件单标识、错误与未知状态、去重和有效期、异步结果访问、配置与启动命令。形成完整正反例后才能据此实现对外接口，不能在实现中临时选择公开写法。

### 对调用方的业务承诺

| 调用意图 | 必要输入或上下文 | 必须可观察的输出 |
| --- | --- | --- |
| 查询账户资金 | 当前已验证账户 | 余额、权益、可用资金、占用/冻结保证金、来源与采集时间 |
| 查询持仓 | 当前账户及明确筛选范围 | 多空、今昨仓、可平/冻结等可验证字段及快照信息 |
| 查询挂单与成交 | 当前账户、状态/合约/委托等筛选语义 | 身份明确的记录、业务状态和数量 |
| 开仓或平仓 | 合约、方向、开平、手数、限价、请求身份 | 请求执行阶段、可确认的委托关联及业务结果 |
| 撤销委托 | 明确的委托身份与请求身份 | 撤销、成交、拒绝或仍无法确认的结果 |
| 管理止盈止损 | 保护对象、数量、触发和报单条件、执行位置 | 条件单身份、参数、启停状态及触发后的委托关联 |
| 获取请求结果 | 已接受请求的身份 | 当前可确认的执行阶段、结果或未知原因 |
| 查询服务能力 | 当前客户端、账户和适配环境 | 就绪情况、限制及阻断原因 |
| 调试接管 | 显式接管/恢复意图 | 自动化已暂停或经重新确认后恢复的状态 |

无法取得的字段不得填零伪装完整输出；接口设计须给出明确的缺失或不支持语义。对客户端未验证的能力，业务层不承诺可用。

### 主链与反例

以下示例约定业务语义，不是最终 HTTP 调用示例，也不包含实际交易授权。

- 正例：调用方要求对明确合约买入开仓 2 手，指定限价。控制器使用该场景已选定的键盘填单或文件导入路径，确认完整参数后提交，再从委托/成交记录返回已确认的身份和结果；不能沿用面板或旧文件中的 1 手。
- 正例：调用方按委托身份撤单，客户端期间显示部分成交。返回已成交和最终剩余状态，不把整笔委托视为从未执行。
- 正例：调用方要求服务器止损，目标柜台能力已经验证，条件单成功建立并启动。返回执行位置和条件状态，不能将创建条件单解释为平仓已经成交。
- 反例：导出动作失败，但目录中存在前一分钟的持仓文件。应报告本次读取失败或明确陈旧状态，不返回“最新持仓”。
- 反例：本次导入窗口异常迟缓，尚不能确认是否已导入或发送。应按当前阶段核对结果并报告，不能切到键盘路径重新下单。
- 反例：批量文件只成功导入部分记录。应停止本批发送并报告已确认的导入情况，不能全选发出或自动重导整份文件。
- 反例：提交后发生超时。应返回结果未知并保留请求身份，不自动再发一笔，也不声称资金未受影响。
- 反例：服务器条件单能力未验证。应拒绝对应请求或要求调用方显式选择已支持方式，不静默改成本地保护。
- 反例：运行中发现快期2版本已变化，或者快捷键焦点不能确认。应停止自动交易并报告环境不匹配，不继续套用旧流程。
- 反例：桥接日志写了“提交按键已发送”，但快期没有可关联事件，委托列表也无法确认结果。不能返回下单成功或直接重试，应按阶段报告未确认结果。
- 反例：读取到上一交易日或其他委托的成功日志。不能据此推进当前请求；日志迟到或轮转后的重复记录同样须正确归属。

### 路径比较与选择验证

比较对象是在同一个华安客户端版本、Wine、硬件、字体、分辨率和配置下，用自动化完成相同业务意图的键盘流程与文件流程。两者的输入、结果正确性、确认步骤和结束条件必须一致；不能拿 CSV 生成时间与完整键盘下单时间比较，也不能拿人工逐字输入作为键盘基准。

先验证流程正确，再重复采样。记录样本数量、完成数量、失败与超时次数，以及成功样本的 P50、P95、最大耗时；失败样本及其耗时单独保留，不能剔除后声称速度提升。后续负责比较的任务须在执行前固定样本量、对比场景和重复轮次，不用单次最快结果选型。

分段记录以下耗时，并保留完整操作耗时：

| 测量段 | 必须包括的操作 |
| --- | --- |
| 准备 | 确认起始页面、切换板块、生成和写完指令文件或填写全部下单字段 |
| 文件选择 | 弹出窗口、取得焦点、输入完整路径或定位文件、确认选择 |
| 导入 | 客户端读文件、解析、刷新列表、显示及关闭结果提示、核对本批参数 |
| 提交 | 定位本次指令、立即发出或启动、处理已知确认、确认返回目标界面 |
| 导出与解析 | 打开保存窗口、输入路径、必要的覆盖确认、等文件写完、解析并校验范围与新鲜度 |
| 结果确认 | 按阶段约定读取并关联日志或补充证据，使用日志时计入其写入可见延迟，核对必要业务数据并形成可返回的结果 |

进入完整 REST 链路后，分别记录排队等待、会话实际处理以及从接受请求到结果可返回的总耗时。两条提交路径使用同等的结果读取标准，并单独展示公共结果读取成本，避免导出瓶颈被算成某一种填单方式的优劣。

下单比较以能够确认委托接受、拒绝或已明确的业务结果为结束点，不把等待市场成交的时间当作填单延迟。条件单设置以创建及所请求的启停状态已确认结束，不计入等待未来价格触发的时间；查询以完整、有效数据可返回结束。无法直接测得的柜台时间只能标为本地观测，不能当作柜台内部延迟。

覆盖单笔开平仓/限价挂单、连续单笔、小批量准备与发送、条件单设置，以及资金/持仓/委托查询的导出。首次弹出文件窗口和重复操作分别测量；批量同时记录首笔等待、整批耗时及每条指令的摊销值，不用批量平均优势掩盖单笔变慢。

文件窗口每次出现、路径是否被记忆、保存覆盖、读取错误和导入确认弹窗均应实际观察；可比较经过验证的完整路径输入等优化，但不预设能取消这些窗口。还要覆盖 headless、VNC 服务运行但无人连接、VNC 已连接，以及连续查询占用队列时交易请求的等待，避免只在空闲桌面测出理想结果。

日志观察开启时，将写入可见延迟、读取/解析/关联耗时和资源占用纳入完整流程，不能只测读文件本身。观察器不合格时使用既定补充来源的成本也须计入；诊断导出不能被隐藏为不计时的后台必要步骤。

选择规则：在正确性和可靠性通过后，文件路径在对应场景完整耗时稳定更快，且 P95、超时与失败情况没有抵消该收益，则选文件路径；更慢则选快捷键。优势不明显或测量结果不稳定时先保留已验证的快捷键路径，定位瓶颈后再评估。没有通过正确性验证的键盘路径不能因文件路径较慢而直接启用。

可以按明确场景分别选择，例如单笔键盘、批量文件；查询导出独立评价，不随提交方式一并切换。选定规则在发布前确定，生产中不通过竞速或重复执行来测量。两种路径均不满足既定时效要求时，停止宣称该能力就绪，不能跳过结果核对或改用未经验证的识图流程。

当前没有实际测量值，也不预设“低于某毫秒”的承诺。具体时效目标、超时和允许的数据新鲜度在对应实施任务中提前确定。离线 mock 可以校验计时和异常逻辑，但不能证明真实 Wine 文件窗口的性能；需要实际客户端或账户的测量按后文的独立验证入口和授权范围执行。

### 必须保留的离线验证范围

- 请求参数、手数、价格和开平语义的正向及拒绝路径。
- 经实际样本确认并脱敏的资金、持仓、委托、成交和条件单导出文件解析。
- 空表、缺列、未知编码、截断写入、选中行导出、旧文件残留及来源区分。
- 导入文件格式与参数、成功数量不符、部分导入、重复导入、本批定位及导入后默认未启动的处理。
- 快捷键前置页面和焦点、输入残留、确认弹窗、排序变化及未知窗口。
