# 中国期货终端桥接的项目初衷与第一版蓝图

## 使用场景与设计初衷

### 要解决的实际问题

用户交易中国境内期货，目标期货公司是华安期货，使用场景围绕 CTP 账户展开。用户在自行接入 CTP 交易时遇到终端信息采集等要求，认为自己处理采集组件、认证流程及相关维护过于麻烦，希望把这些工作交给现成交易客户端。

目标使用方式是：部署一个容器，使用现有期货账户正常登录交易客户端，外部程序通过 REST API 查询账户和发送明确的交易指令。客户端负责其自身的终端信息采集、身份认证、柜台连接、报单和接收回报，桥接服务负责操作客户端并转换可观察的结果。

用户希望优先使用免费、轻巧、内存占用较低、适用于普通账户登录交易的客户端，不希望为这个方案购买专业版 API 服务，也不希望重新承担一套自研 CTP 接入的工作。是否可直接使用华安具体客户端、账户是否具备所需权限，仍须按实际账户和客户端核实，不能把使用偏好写成已经验证的事实。

需要覆盖的常用业务包括：

- 余额、权益、可用资金、已用保证金和冻结保证金查询。
- 多空持仓、今昨仓、可平与冻结数量查询。
- 挂单、委托状态、成交结果查询。
- 开仓、平仓、限价挂单、撤单，以及每笔委托的手数设置。
- 止盈、止损及对应条件单的查询、修改、取消和状态确认。
- 登录、断线、客户端弹窗、拒单、导出失败等异常的识别和对外反馈。

项目提供交易终端的执行与查询能力，不负责替用户选择交易机会、制定策略或作出投资决策。“轻量客户端”是运行资源诉求，不代表第一版承诺高频交易或柜台 API 级延迟。

### 项目身份与工作范围

项目名称为 `cn-futures-bridge`，表示面向中国期货的交易桥接。名称不绑定某个软件厂商；快期2是第一版适配对象，未来更换终端时仍沿用项目名称和业务目标。

项目独立位于 `/home/hxse/dev/cn-futures-bridge/`。此前的需求讨论发生在 `ccxt-proxy2` 工作区，但该项目不是本项目的运行依赖，也不是本任务的修改范围；不得向其添加客户端适配、容器、任务文档或业务接口。

本任务保留完整的项目动机和已确定取舍，同时承载最小启动阶段：先支持 SimNow，落地基础代码、配置及镜像，让快期2启动到登录窗口。账号先留空，用户填写后再继续登录、读取和交易联调；本阶段不执行这些账号操作。

调试阶段只使用 SimNow。原生模拟专用旧下载链接失效时，可使用厂商官方普通快期2完整包中已有的“上期技术 / 9999”站点；保留该站点原生服务器和认证参数，配置中只保留模拟站点，不自行接入 CTP。模拟站点的实际登录与柜台兼容性须在用户提供账号后验证。

### 客户端选择的形成

最初的候选包括文华财经和快期等常见交易软件。用户特别关注快期面向快速手工下单的轻量终端，最终明确以普通快期2 / V2 / Q7 作为第一版候选。

选择快期2的关键不是要求厂商提供 API，而是它已有丰富的键盘操作和文件导入导出能力。文件可以承载待发送的交易参数，键盘可以逐项填单，也可以触发文件导入、发送和启停。两种路径按实际业务的正确性、稳定性和完整流程耗时选择，最后才使用 GUI 识别。

GUI 识别兜底是项目约束。不能因为图像识别工具方便，就把每次查询和交易都设计成截图、OCR 或视觉模型操作；也不能把界面控件识别提升为替代快捷键与文件路径的默认主链。

### 文件路径与操作速度的取舍

快期2手册说明可将预埋/条件单导出为 CSV，编辑价格、手数等参数后重新导入；手工预埋单可立即发出，导入的预埋/条件单默认未启动。这使“生成文件 → 导入 → 核对 → 发送或启动”成为新增委托的候选路径，可以减少逐字段键盘输入。[预埋条件单手册](https://doc.shinnytech.com/q72/latest/7.html)

用户最担心的是每次导入都要打开文件选择窗口，随后输入路径、等待读取、确认导入结果，再回到交易页面发送；导出也可能要经过保存窗口及覆盖确认。文件格式易于生成，不代表这些完整交互比快捷键填单更快，相关耗时目前没有实测数据。

因此，不预先把文件导入设为统一首选。正确性和结果确认要求相同的情况下，文件路径稳定更快就采用文件路径，更慢就采用快捷键；优势不明显时不因减少填单字段而认定文件更优。单笔、连续单笔和小批量的固定弹窗成本不同，须分别比较，不能用批量平均耗时代替单笔响应速度。

导入和导出也要分开评估：交易参数通过哪种路径提交，与资金、持仓、委托如何可靠读取，是两个选择。即使下单最终使用快捷键，查询仍可使用经过时效验证的导出。文件导入尚未证实支持撤销或修改已进入柜台的订单，也未证实存在无需界面动作的目录监控接口；这些能力不能因采用文件路径而被假定具备。

### 日志与异常观察的取舍

用户希望在每个操作阶段后检查日志，以减少对 GUI 错误识别的依赖。快期2官方手册确认存在“选项 → 打开日志目录”的入口，但没有承诺日志是实时可读文本，也没有说明是否包含每一步动作、完整拒单原因或足够的委托关联字段。[快期日志说明](https://doc.shinnytech.com/q72/latest/3.html)

若日志格式、事件覆盖和写入时效验证通过，优先持续读取本地新增日志，在阶段检查点关联结果；不默认每阶段通过菜单全量导出日志。这样可以避免重复打开文件窗口、保存或打包日志的成本，具体收益仍须实测。

桥接服务的操作日志记录请求、动作和耗时；快期日志提供客户端实际记录的事件；委托、成交和持仓等业务记录用于核对真实结果。三者不能互相冒充：“按键已发送”或“没有错误日志”不能证明客户端已执行，也不能证明订单已被柜台接受。

日志可观察到的异常优先由日志与业务状态核对，焦点错误、文件窗口未响应或无日志的弹窗仍需要界面检查和截图兜底。日志中的时间接近不等于属于同一请求，不能把历史事件、其他订单或异步回报误关联到本次操作。

### 对 MT5 容器项目的参考

用户提供的参考项目是 [gmag11/MetaTrader5-Docker](https://github.com/gmag11/MetaTrader5-Docker)。其价值在于展示了容器中运行 Windows 交易终端、保留客户端状态并提供远程桌面的部署方式。

该项目的交易接口链路依赖 `mt5linux`、RPyC 和官方 `MetaTrader5` Python 库。Windows Python 环境在 Wine 中调用官方库，官方库通过本机 IPC 与 MT5 终端通信，终端连接经纪商。资金、持仓和下单结果来自接口返回，而不是截图识别。项目自身主要暴露 Python RPC，并未直接实现所需的 REST 业务接口。[启动脚本](https://github.com/gmag11/MetaTrader5-Docker/blob/main/Metatrader/start.sh)、[官方 Python 接口](https://www.mql5.com/en/docs/python_metatrader5)

当前 `mt5linux` 主分支还带有容器管理和界面辅助：配套脚本使用 `xdotool` 搜索交易服务器、处理登录和更新弹窗。它的交易与查询主体仍是 SDK 调用。不能把“存在少量辅助自动化”解释为所有接口均通过 GUI 实现。[交易转发源码](https://github.com/lucas-campagna/mt5linux/blob/master/mt5linux/metatrader5.py)、[RPC 实现](https://github.com/lucas-campagna/mt5linux/blob/master/mt5linux/_container_manager.py)、[辅助脚本](https://github.com/lucas-campagna/mt5linux/blob/master/docker/src/automation.sh)

普通快期2的公开资料中尚未查到同类完整终端交易 SDK。快期专业版虽有本地 API，但官方说明其为只读数据访问，不提供下单、撤单或改单。本项目因此借鉴 MT5 的部署结构，自行设计快期2的操作和结果读取层，不把 MT5 SDK 转发方案视为可直接复用的交易实现。[快期专业版 API 说明](https://publish2.shinnytech.com/doc/qpro/latest/ai_editor/qpro_httpserver.html)

### 已有调研事实与证据边界

下列资料核对时间为 2026-09-19，记录的是公开文档和源码信息，不代表已经验证华安账户或具体安装包。后续实施应重新核对与所选安装包相关的内容。

| 已确认的资料事实 | 对项目的影响 | 依据 |
| --- | --- | --- |
| 快期2手册提供纯键盘填单、板块切换、撤单和部分平仓快捷键 | 可以构建确定的键盘流程，并作为文件路径的比较基准 | [软件操作](https://doc.shinnytech.com/q72/latest/2.html) |
| 快期2手册说明列表可通过右键菜单导出 | 持仓、委托等列表优先尝试结构化文件读取 | [选项配置与列表导出](https://doc.shinnytech.com/q72/latest/3.html) |
| 快期2手册提供打开日志目录的入口 | 先验证本地日志能否作为增量事件来源，不等同于已有完整日志 API | [快期日志路径](https://doc.shinnytech.com/q72/latest/3.html) |
| 资金详情区分柜台数据和快期本地计算数据 | 返回值要保留来源，不能混淆同名资金指标 | [板块说明](https://doc.shinnytech.com/q72/latest/9.html) |
| 快期2支持预埋/条件单 CSV 导入导出、手工预埋单立即发出，导入后默认未启动 | 文件可承担新增指令的参数准备；导入、启动和柜台报单仍须分别确认 | [预埋条件单](https://doc.shinnytech.com/q72/latest/7.html) |
| 公开更新记录涉及界面、快捷键、条件单和业务指令变化 | 自动化必须与完整客户端版本及配置绑定 | [快期2更新记录](https://www.shinnytech.com/pages/q72-release-note) |
| 期货公司曾要求快期 V2/V3 必须升级，否则可能不能登录交易 | 固定版本不等于永久兼容柜台 | [大地期货 2019 年通知](https://www.ddqh.com/news/info/918.html) |
| 国海良时的一次 CTP 升级将快期 V2 列为需更新且支持自动在线升级的客户端 | 安装包固定之外，还要控制运行时版本变化 | [CTP 客户端升级说明](https://www.ghlsqh.com.cn/f/27771/附件CTP客户端升级情况说明.pdf) |

尚未查到快期2“每次发布新版就统一禁用全部旧版”的官方规则，也未确认华安当前最低兼容版本、自动升级是否可关闭、客户端是否会在登录或退出时替换文件。其他期货公司的通知只能证明存在这种机制，不能当成华安的具体政策。

调研访问华安下载入口时遇到网页校验，未取得并执行华安当前的快期2安装包。Wine 下的采集、认证、登录、资金导出、止盈止损设置和完整异常读取均未实测；日志的实际目录、格式、编码、写入延迟、事件覆盖、关联字段和轮转行为也尚未验证。

列表导出说明也不等于所有字段都已验证可导出：需要确认资金详情是否属于可导出列表、导出的范围、编码、表头、委托编号、状态字段和写入完成条件。导入还须确认具体模板、文件选择与确认窗口、重复和部分导入行为，以及整个流程相对快捷键的耗时。快捷键以选定安装包的实际行为为准，不能直接混用不同版本手册。

没有可信的华安版 Wine 运行内存测量。安装包大小、镜像大小、持久卷占用和运行内存是不同指标；MT5 参考项目描述的镜像体积变化不能用来推算快期内存，也不能全部归因于 VNC。[MT5 项目说明](https://github.com/gmag11/MetaTrader5-Docker)

## 方案对比

| 方案 | 收益 | 成本与限制 | 本项目取舍 |
| --- | --- | --- | --- |
| 自行直连 CTP | 结构化交易与回报，交互直接 | 仍需处理用户希望交给客户端的采集和接入维护 | 第一版不采用 |
| 普通快期2的快捷键填单与操作 | 复用客户端交易流程，避免导入文件的固定交互成本 | 依赖焦点、字段数量和输入后的核对 | 第一版候选，文件路径更慢时采用 |
| 普通快期2的文件导入导出 | 结构化准备指令和读取结果，可能减少批量填单动作 | 文件选择、保存、确认及导出等待可能拖慢单笔业务 | 正确性通过且完整流程稳定更快时采用 |
| 增量读取快期日志并核对业务状态 | 捕获可观察事件，减少错误识图和重复导出 | 日志可读性、完整性、关联能力和时效尚待验证 | 按阶段验证后优先使用，GUI 处理未覆盖交互 |
| 快期专业版 API 或其他 SDK 产品 | 部分数据可直接程序访问 | 产品、权限或费用不同，专业版本地 API 也不提供交易操作 | 不作为第一版依赖 |
| 截图、OCR 或视觉模型承担全部操作 | 可以覆盖不暴露控件的界面 | 对字体、布局、遮挡和数值识别敏感，资源与维护成本更高 | 仅对未覆盖能力局部兜底 |
| Linux + Wine 的普通容器 | 符合 Podman 部署和减少系统开销的偏好 | Wine、采集组件、运行库、字体和位数兼容性待验证 | 优先验证 |
| 完整 Windows 桌面系统或虚拟机 | Windows 客户端兼容路径更直接 | 系统与会话维护成本、磁盘和内存占用增加 | 用户接受的备选方向 |

Windows 备选指带交互桌面的完整系统，例如 Windows Server Desktop Experience 或虚拟机。标准 Windows Server 容器不提供本方案需要的交互桌面。`dockur/windows` 可以在容器中承载 QEMU/KVM 虚拟机，但它仍运行完整 Windows，并非消除了虚拟机成本。[微软说明](https://learn.microsoft.com/en-us/virtualization/windowscontainers/quick-start/lift-shift-to-containers)、[dockur/windows](https://github.com/dockur/windows)

第一版交付带 VNC 和不带 VNC 的两个镜像变体，共用同一套程序和运行环境，仅远程桌面组件及必要的服务入口不同。一份 Containerfile 的公共构建层包含快期2、Wine、字体、虚拟屏幕、自动化、日志观察和 REST 服务，VNC 变体增加远程查看和操作能力。

不带 VNC 的变体仍有内部 GUI 和虚拟屏幕，可以截图并读取日志；带 VNC 的变体供实时排查窗口、焦点、文件选择和弹窗。两者的客户端版本、布局、显示配置、业务规则和 API 一致，避免调试环境与日常运行环境采用不同实现。

部署时同一账户二选一运行，切换镜像沿用兼容的持久化数据并重新核对会话与未完成请求。停止旧实例再启动另一变体不等于无中断热切换，不能在同一个 Wine 目录上同时启动两套进程。

Xvfb 可以提供内存中的虚拟屏幕，x11vnc 可把该显示暴露给调试端，noVNC 允许用户从自己的浏览器访问。容器不需要为此安装完整浏览器。[Xvfb](https://www.x.org/docs/man/man.pdf)、[x11vnc](https://github.com/LibVNC/x11vnc)、[noVNC](https://github.com/novnc/noVNC)

## 取舍结论

1. 以独立项目维护通用业务边界。调试先使用快期2的 SimNow 环境，最终业务目标仍是华安账户；不把模拟环境通过视为华安实盘通过。
2. Linux + Wine 优先。第一版的 headless 与 VNC 两个镜像仅远程桌面组件不同，共享字体、虚拟屏幕、自动化和 REST 业务实现；Windows 是兼容性不通过时的备选实施方向。
3. 快捷键与文件导入导出按业务分别实测择优，文件选择窗口等固定成本必须计入；GUI 识别继续兜底。选定路径属于版本适配方案，不在运行中因某次变慢或结果未知而改用另一条路径重复执行。
4. 固定已验证的华安客户端版本，并保留受控升级路径。不能承诺永不升级，也不能以屏蔽更新代替柜台兼容性验证。
5. 每笔交易明确合约、方向、开平、手数与价格；每个阶段检查对应结果。日志验证通过后优先增量读取，并结合业务状态核对；支持异常和结果未知，不能用操作日志或没有报错代替柜台接受。
6. 止盈止损优先使用客户端已有条件单能力，区分本地和服务器执行。资源开销与业务可用性用实测说明，不提前承诺具体内存、延迟或无人值守成功率。
7. 客户端承担自身的采集与认证不等于相关报告要求消失。本项目不把界面自动化描述为免除程序化交易报告的保证，不以伪造采集信息或冒用软件身份作为实现路径。[证监会相关说明](https://www.csrc.gov.cn/csrc/c100028/c7564353/content.shtml)
8. 首个运行阶段只交付空账号启动和诊断，配置使用 config.toml 与 config.example.toml；具体约定见 [spec_01_bootstrap.md](spec_01_bootstrap.md)。完整交易蓝图仍保留在 [spec.md](spec.md)，业务接口在对应能力确认后冻结。
