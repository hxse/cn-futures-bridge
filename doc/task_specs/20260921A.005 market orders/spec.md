# 市价模拟与路由状态核验

## 任务边界

在现有 change 内检查、更新全部八个业务路由。交付限价模拟市价、三种写操作的前后 CSV 观察、三种 CSV 查询的一致性核对，以及所有路由共用的通知清障。资金继续读取原生详情服务器列，品种交易状态继续读取原生状态；不伪造对应 CSV。

保持路由方法、名称、输入、环境隔离、单账户 FIFO、幂等、防重发及容量治理。响应允许增加必要的执行参数与观察事实。指定平今/平昨、FOK、套保套利、会话编号撤单等未核验参数不自动开放；限价 IOC 因复用市价模拟的同一路径而纳入验证。

替换原生市价执行及其能力说明和测试，不维持两套市价链路。开仓、普通平仓的实际发送引用捕获、精确订单及成交关联纳入范围；策略、自动追单、自动补单不在范围。结束时须清理本次模拟测试的仓位和活动委托，不改变人工交易。

## 任务规范

### 通知与执行权

精确识别“下单成功”“下单失败”“撤单成功(即时单)”“撤单失败(即时单)”及其批次编号标题，以及既有成交通知，核对进程、GUI 线程、主窗口 owner、标题、直接子控件及正文结构。记录并关闭结果通知，但其文字不参与提交、拒绝、成交或仓位状态计算。未知窗口仍保留现场并暂停，不能盲点。

所有路由的前后检查和通知处理归属同一 GUI 执行权。重复通知不能耗尽启动文档的终身计数；运行期通过同一窗口去重、关闭核对及每次基线期限限制处理，不增加后台点击线程。暂停时不操作。通知读取以 Unicode 实际文本为准，不把 ANSI 长度估计当作实际字符数。

### 市价模拟与限价

市价入口不接受 price 或 time_in_force，唯一语义为限价 IOC、允许部分成交。买入采用当前合约涨停价，卖出采用跌停价；按终端原生状态确认连续交易，校验正数、有限值、步长、涨跌停和限价最小/最大手数。资料无效时发送前报错，不使用零或旧的请求缓存，不转 GFD、不自动拆单。

实际成交按市场撮合，限价不等于成交价；可能零成交、部分成交或柜台拒绝。返回明确的实际委托价格、有效期及模拟标记。

限价 GFD 使用 CSV 导入；限价 IOC 和市价模拟使用下单板填写明确数值价格和 FAK，生成本地手动预埋单。通过 CSV 与只读原生预埋字段核对价格、买卖、开平、手数、投保、价格选择器、时间条件和数量条件，再用唯一快捷键发送。收尾只清理本次记录并恢复表单，不调用内部交易函数。

### CSV 证据与有界观察

开平仓发送前保存委托、成交、持仓快照；发送后按默认最多 3 轮、轮间 100 ms 回读。次数与间隔属于公共 execution 配置，具备范围校验。已有明确 CSV 结果时提前结束，缺少结果不无限等待；每轮是新的导出文件，不读取旧文件。

委托用于观察状态、成交量、剩余量和拒绝原因；成交用于观察成交明细；持仓用于复核目标合约实际仓位。比较须排除旧记录状态变化、保持交易日及会话不变，不只凭持仓差值判断结果。CSV 按 GB18030 严格解析并核对字段和数量，不把读取失败当空数组。

新建委托在唯一预埋记录的正常快捷键发送期间捕获实际 OrderRef，关联键为账户命名空间、交易日、FrontID、SessionID、OrderRef。引用与确定的订单编号持久化到防重发记录；返回后或恢复中不得从参数候选重新认领订单。撤单沿用已有精确订单编号。

捕获仅适配已校验哈希的固定程序和核心 DLL。在唯一 GUI 线程中临时观察手动预埋发送入口，其内部同步通知只复制非凭证字段，不修改报单参数、不主动调用交易函数。原通知槽非空、版本/入口不符时在发送前拒绝；一次发送须恰好取得一条匹配预埋 ID、合约、买卖、开平、价格、手数和有效期的引用。没有引用或多条引用保留 unknown，不回退到 CSV 差集。通知槽在原调用返回时恢复，入口在捕获结束或收尾时恢复；恢复未确认即隔离 GUI。

通过安全的订单列表读取器按完整引用精确筛选，取得交易所编号后按该编号核对 CSV。拒单尚无交易所编号时使用同一引用对应的原生订单事实；不得靠界面通知判定。原生成交对象的所属订单与完整引用一致才可将其成交编号关联到成交 CSV，终态有成交时还需成交量核对一致。持仓保持前后真实快照，不用持仓差值归属订单。CSV 缺失、冲突或更新未到齐保留 pending/unavailable，不伪造终态。

原生编号的定长前置空格与 CSV 显示编号统一为去除前置空格的值；调用方传入的 CSV 编号仍不擅自改写。引用可用于当前交易日的独立订单查询；不使用不明约束的 GetOrderListByRequestID，不承诺历史回补。进程中断保留已持久化的引用和编号，不自动重发；捕获尚未落盘的中断仍为未知。

发送一次后，本地“已发送”仍是提交事实。结果观察超时或缺失保留 submitted 和待确认观察结果；读取错误单独报告为观察不可用，若涉及断线、GUI 或存储异常则按既有机制隔离，保留已知副作用。通知不参与此判断，不重复发送。

撤单兼容已核对的确认框及关闭确认框的终端设置。只按一次 Delete；有确认框则核对精确合约/编号后确认，没有确认框则依靠完整委托 CSV 核对撤销或已成交。无法确认动作影响时返回 unknown，不假装撤单成功。

### 五个查询路由

委托、成交、持仓查询读取至少两次、最多配置次数的快照。以稳定身份和业务数量/状态比较，持仓不因浮动盈亏变化而不断等待；返回最后一次完整快照及 stable/changing 一致性标记，不要求市场停止变化。读取失败明确报错。每次读取和结束时核对会话，发生切换不得混合不同会话快照。

资金查询只读服务器列、关闭本次资金窗口并核对基线；不根据通知或仓位推算余额。交易状态读取原生品种编码，未知、断线报错，不能转换为休盘；正常查询不切页、不使用日历或额外固定 sleep。

## 公开接口与用户写法

八个路由和既有请求字段保留。例如：

```bash
curl -X POST 'http://127.0.0.1:45173/cfb/create_market_order' -H 'Content-Type: application/json' -H 'Idempotency-Key: market-open-001' -d '{"mode":"sandbox","exchange_id":"DCE","instrument_id":"m2701","side":"buy","offset":"open","volume":1}'
```

POST 正常返回仍为 202/submitted。execution 表达实际委托参数；identity 包含 exchange_id、instrument_id、trading_day、front_id、session_id、order_ref。order_id 只填写该引用对应的真实交易所编号，未分配时为 null。verification.correlation=order_ref、source=terminal_csv_and_native，orders 和 trades 仅包含精确关联记录；observed 表示已观察到约定订单状态及其成交核对，未到齐为 pending，身份冲突为 ambiguous，读取失败为 unavailable。撤单保留 correlation=order_id、source=terminal_csv。

fetch_orders 新增可选 trading_day/front_id/session_id/order_ref，须同时提供且指定 exchange_id/instrument_id，与 order_sys_id 互斥。仅支持当前交易日，旧交易日明确报能力错误，不返回空结果冒充已查询。示例：

```bash
curl 'http://127.0.0.1:45173/cfb/fetch_orders?mode=sandbox&exchange_id=DCE&instrument_id=m2701&trading_day=20260924&front_id=3&session_id=123&order_ref=18'
```

编号仅为格式示例，调用方使用实际 POST 返回的 identity。部分引用参数报 422。按引用查询的结果附 identity，source=terminal_csv_and_native；没有该引用的订单返回空列表，不推断失败。错误响应及重启后的中断结果保留已取得的 identity/order_id。

三个 CSV GET 新增 consistency=stable/changing；资金和交易状态保留原结构与来源。mode 不匹配仍 409；非法输入 422；未支持分支 501；查询或连接失败保持既有错误分类。已提交后的收尾错误保留 submitted，调用方不得以 HTTP 非 2xx 推断没有下单。

```toml
[execution]
csv_confirmation_attempts = 3
csv_confirmation_interval_ms = 100
```

## 测试、验证与阶段过渡

运行正式入口 just check、少量离线 just test、just build。离线覆盖限价模拟与预埋条件、发送捕获缺失/错配/重复、同参订单不会被认领、完整引用查询参数、无订单号拒单、成交匹配及延迟、引用持久化与重启不重发、查询一致性和错误、通知不参与状态判断。禁止默认测试访问交易网络。

本轮授权的独立在线调试只在身份明确的 SimNow 进行，一手开平仓、非成交挂单后撤单，逐一查询八个路由并核对真实委托和成交；需要等待时设置期限，遇到异常停止该写操作，不盲重试。验证结果通知自动关闭、无遗留本地记录、未知结果不重发、请求后队列恢复。实盘禁止交易验证。

精确关联集成须通过正式 HTTP 市价模拟入口执行一手开仓和对应平仓，记录从发送 HTTP 到完整响应的总耗时及服务步骤耗时，核对各自引用、订单号、成交和前后持仓，并只读查询复核。耗时是单次实测，不当作长期延迟保证；不能用临时探针耗时替代正式路由耗时。

历史幂等响应须原样重放，允许其保留 snapshot_delta 和空标识；新请求不再产生该关联方式。这是历史结果兼容，不保留旧差集认领实现。纯本地拒单可能在终端重启后消失，已保存的请求响应仍保留事实，不承诺终端全量历史回补。

构建前先以不发送的本地预埋单核对固定终端数值限价 IOC 的真实枚举；上线前验证柜台是否接受。若模拟环境不接受 IOC，明确报告能力阻断，不未经说明改成会遗留挂单的 GFD。测试时停用后台 GUI 派发，临时探针用独立命名空间，完成后清理；最终恢复正式队列。同步受影响 current spec、OpenAPI 和 README，不将本次执行统计写入规范。
