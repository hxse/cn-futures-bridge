# 市价模拟与路由状态核验

## 使用场景与设计初衷

用户需要通过八个 HTTP 路由操作单个快期账户。当前以 SimNow 验证，实盘功能不受只读限制，但 AI 不得以测试名义在实盘交易。程序与 VNC 手动操作必须使用同一套终端事实。

界面可以展示“下单成功”而订单仍未成交，也可能已经成交却因通知未关闭导致接口收尾失败。用户要求通知只负责记录、关闭，交易状态独立来自 CSV；开平仓前后保留快照并有限次数重新读取，不能因仓位未变判定失败后重发。

用户已明确接受使用限价模拟接近市价的效果。此能力须公开真实限价与有效期，不声称原生市价。自动交易还要求把本次请求关联到确定订单，因此开平仓须在实际发送时捕获报单引用，不能用相似参数或快照增量认领订单。

## 方案对比

只看通知或持仓差值不能区分挂单、拒单、部分成交和其他已有委托的成交。预埋记录的缓存引用也可能与真正发送的引用不同。选择固定版本内部发送通知中的实际引用，与账户、交易日、前置和会话绑定；CSV 保留为已确定订单、成交及仓位的事实核对来源。

限价 GFD 优先使用无弹窗 CSV。IOC 不能由现有导入格式表达，复用下单板及手动预埋单回读；通过快捷键发送，剩余量由 IOC 本身撤销，不引入事后追价或反复补单。

## 取舍结论

市价入口使用买入涨停价、卖出跌停价的限价 IOC。保留八个路由及既有参数，响应增加实际引用与精确观察结果；订单查询可选按完整引用查询。不改变 submitted 仅代表提交的语义。

交易按同一 FIFO 保留前后快照并有界回读；普通 CSV 查询核对连续快照，资金和交易状态保留各自已验证的专用来源。通知处理与交易判断完全分离。
