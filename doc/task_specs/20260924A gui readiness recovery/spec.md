# 界面快速检查与恢复

## 任务边界

交付八个业务路由共用的轻量前置检查和收尾检查，已知残留菜单及资金详情的定向恢复，空标题对话框检测，SimNow 全天站点的空结算单确认，以及表单恢复的无效操作削减。同步受影响 current spec 和使用说明。

保持单账户 FIFO、暂停/恢复、环境隔离、真实报单引用、订单确认、防重发、断线恢复及工件容量规则。完整窗口树仍用于需要控件数据的业务步骤；旧的仅用于就绪判断的全树扫描由摘要替代，不保留平行的旧就绪链路。

不增加路由、配置、通用任意窗口点击能力，不修改订单参数、柜台订单或用户预埋记录。未知交易确认不自动确认，不通过重启消除未决交易。无需新增交易验收；本任务不进行实盘或模拟盘报撤单。

停止线：正常状态无需截图、CSV、键盘或固定等待即可通过；明确可恢复状态有界恢复后复核；不可恢复状态阻断；恢复和正常查询仍共用原执行权。性能与功能结果只在回复报告。

## 任务规范

### 轻量检查与恢复

原生命令在受控进程及 GUI 线程中读取摘要：唯一配置主窗、可用状态、焦点、菜单模式及归属、鼠标捕获、修饰键状态、可见对话框数量、已识别通知等待状态、可恢复资金窗口和未知阻塞数量。不枚举正常主窗口的子控件、下拉列表或账户正文。

所有可见顶层 #32770 均纳入检查，包括空标题。已识别通知沿用既有精确模板与分阶段处理；摘要读取同样维护通知关闭后的去重状态。非当前 GUI 线程的对话框只能报告阻塞，不能自动操作。

“确认结算单”保留既有进程、线程、owner、按钮 1/2 和只读 RichEdit20A/7601 校验。仅当配置主窗精确对应“上期技术-全天站点”，正文原生长度为零，按钮可用，且主窗下唯一可见 Static/1257 严格显示 HH:MM:SS、Tab、“查询结算单成功”时，允许稳定至少 250 ms 后确认空结算单。条件中断须重置观察时间，不确认空标题、加载中的正文、查询失败或其他环境的空结算单。非空正文继续按原完整结算正文规则验证；不根据这条状态文字判断任何订单或成交。

空结算确认仍由原 GUI 执行权异步投递精确 IDOK，一次显示不重复投递，计入原结算确认及会话预算，并记录独立空结算确认计数，不记录正文。结算窗口隐藏后清除去重和空正文计时，缓存句柄再次显示时重新核验。

恢复前再次核对目标身份和当前摘要，不依赖上一次句柄永久有效。菜单只允许取消属于受控主窗口的活动菜单，不选择菜单项；资金详情须核对精确标题、对话框类、主窗口 owner、资金正文控件身份和可关闭属性，只投递关闭。未知交易确认和不明捕获阻断，不发送通用 Enter/Esc。每个异常目标在一次检查中至多投递一次恢复，通知继续沿用既有分阶段去重。

健康摘要直接通过，不固定 sleep；待处理通知或已投递恢复时按现有 poll_interval_ms 轮询，受 step_timeout_ms/剩余启动期限限制。恢复后重新读摘要确认窗口隐藏、菜单退出和主窗口可用；超时返回 GUI_RESET_FAILED 或原有超时错误，并停止派发。日志记录类型、目标句柄、动作及耗时，不记录资金正文。

前置检查在取得 FIFO 执行权、核对账户和会话之后运行。只在需要键盘时处理修饰键与焦点；后台 CSV 和原生状态查询不强制激活或切页。空闲探测、显式 resume 复用同一检查，pause 后不操作。poisoned 调用不再执行恢复。

### 收尾与业务窗口

资金查询期间主动打开的详情窗口不被检查提前关闭；读取后仍定向关闭并验证。业务内部需要完整快照时继续扫描控件，遇到可恢复阻塞时交给共用恢复入口，再重新读取，不跨界面变化缓存。

finally 保留本次捕获恢复、已归属预埋清理、已归属设置窗口关闭及表单恢复。只有这些步骤需要先处理通知时才单独扫描通知；无业务残留的查询直接做最终轻量检查，避免相邻重复完整扫描。收尾失败保留提交状态与订单身份并隔离。

恢复表单时文本已一致则跳过设置、Tab 和等待；正常填参仍提交编辑，不能把尚未失焦的相同文字当作已经生效。单选与有效期沿用只在变化时修改的规则。合约发生变化后重新读后续字段，最终完整比对恢复结果。就绪检查不擅自删除或重建业务对象。

## 公开接口与用户写法

八个 /cfb 路由、输入输出、默认配置保持不变，无新增恢复路由。用户继续使用 just pause 人工接管、just resume 核对并恢复；这些命令不补发交易。

例如调用 `GET /cfb/fetch_positions?mode=sandbox` 时，正常界面直接进入 CSV 查询；若存在可精确识别的资金详情，先关闭并核对，再查询。若出现未知“确认下单”窗口或空标题对话框，返回 GUI_RESET_FAILED 并停止后续派发，不能当作查询成功。

同一请求执行中出现原生超时仍进入 poisoned 隔离，不允许以复位覆盖原操作未结束事实。已提交订单的 HTTP 收尾错误继续保留已知 order_id、identity 和提交状态。

## 测试、验证与阶段过渡

必需通过 just check、just test、just build。离线检查覆盖健康状态无恢复动作、已知窗口恢复及回读、未知/空标题窗口阻断、菜单归属、恢复超时、poisoned 不再操作、修饰键按需处理、表单字段不变时跳过且变化后重新读取。更新既有通知检查使其验证共用入口的真实契约，不放宽交易确认模板。

原生恢复用独立 Wine 窗口夹具验证：正常窗口、资金模板、同名但结构不符、空标题窗口、菜单取消及错误归属；夹具不启动快期或连接账户，属于离线检查。正式构建严格编译原生 helper，独立调试产物不进入镜像主链。

空结算使用原生 RichEdit 和按钮夹具验证全天站点正例、等待期与条件中断、失败/缺失/不唯一状态控件、普通模拟及实盘空正文拒绝、非空完整正文原规则、隐藏后的句柄复用与不重复投递。用户授权的现场仅确认当前结算窗口，并以只读查询核对服务恢复，不进行报撤单。
部署后只读检查现有服务状态及查询；界面恢复调试只操作可关闭的非交易窗口，不进行报单、平仓或撤单。记录健康检查和已知恢复耗时，不把旧开平仓总耗时当作新复位耗时。新原生协议与 Python 同镜像更新，不热换仍在使用的 helper。
